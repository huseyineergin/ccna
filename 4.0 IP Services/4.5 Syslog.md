# 4.5 Syslog
## Syslog
Syslog is a protocol used by computers, servers, routers and other network devices to generate, transmit and collect log messages about system activity and events.
- Syslog is an industry standard protocol for message logging.
- On network devices, syslog can be used to log events such as changes in interface status, changes in OSPF neighbor status and system restarts.
- The messages can be displayed in the CLI, saved in the device's RAM or sent to an external syslog server.
- Syslog and SNMP are both used for device monitoring and troubleshooting. They are complementary, but their functionalities differ.
## Syslog Message Format
A typical syslog message includes:
- **Sequence Number**: A sequence number that indicates the order of the messages.
	- `service sequence-numbers` command enables sequence numbers in syslog messages.
- **Timestamp**: A timestamp that indicates when the message was generated.
	- `service timestamps log [datetime | uptime]` command enables timestamps in syslog messages.
- **Facility**: A value that identifies which process on the device generated the message.
- **Severity**: A number that represents the severity of the logged event.
- **MNEMONIC**: A short code that describes what happened.
- **Description**: Detailed information about the event being reported.

In Cisco IOS, syslog messages follow the format `seq: timestamp: %facility-severity-MNEMONIC: description`.
- `*Feb 11 03:02:55.304: %LINK-3-UPDOWN: Interface GigabitEthernet0/0, changed state to up`
- `000043: *Feb 11 05:06:43.331: %SYS-5-CONFIG_I: Configured from console by admin on console`
## Syslog Severity Levels
Syslog defines eight severity levels, numbered from 0 (most severe) to 7 (least severe).

| Level |   Severity    |  Keyword  |            Description             |
| :---: | :-----------: | :-------: | :--------------------------------: |
|   0   |   Emergency   |  `emerg`  |        System is unusable.         |
|   1   |     Alert     |  `alert`  | Action must be taken immediately.  |
|   2   |   Critical    |  `crit`   |        Critical conditions.        |
|   3   |     Error     |  `errr`   |         Error conditions.          |
|   4   |    Warning    | `warning` |        Warning conditions.         |
|   5   |    Notice     | `notice`  | Normal but significant conditions. |
|   6   | Informational |  `info`   |      Informational messages.       |
|   7   |   Debugging   |  `debug`  |       Debug-level messages.        |
## Syslog Logging Locations
Generated syslog messages may be directed to various destinations.
- **Console**: Displays messages on the device's physical console session when connected to the device via the console port.
	- `logging console <severity>` command configures the severity level of messages displayed on the console.
	- `logging synchronous` command configures the console or terminal line to redisplay the current command prompt on a new line when a message appears.
- **VTY (Terminal)**: Displays messages in remote sessions such as SSH or Telnet, when enabled for that session. It is disabled by default.
	- `logging monitor <severity>` command configures the severity level of messages displayed on terminal lines.
	- `terminal monitor` command enables the display of messages on the current terminal session.
- **Buffer (RAM)**: Stores messages temporarily in the device's memory. Messages are lost after a reload.
	- `logging buffered [<buffer-size>] <severity>` command configures the severity level of messages stored in the device's RAM logging buffer.
	- Messages can be viewed using the `show logging` command.
- **External Server**: Sends messages to a remote server. Syslog servers will listen for messages on **UDP port 514**.
	- `logging [host] <ip-address>` command configures a remote syslog server to which the device sends messages.
	- `logging trap <severity>` command configures the severity level of messages sent to a remote syslog server.
## Syslog vs SNMP
Syslog and SNMP are both used for monitoring and troubleshooting of devices. They are complementary, but their functionalities are different.
- Syslog is used for message logging.
	- Events that occur within the system are categorized by facility and severity and then logged.
	- Used for system management, analysis and troubleshooting.
	- Messages are sent from devices to the server. The server cannot actively retrieve information from devices or modify variables.
- SNMP is used to retrieve and organize information about SNMP managed devices.
	- Examples include IP addresses, interface status, temperature and CPU usage.
	- SNMP servers can query the clients and modify variables on the clients.
