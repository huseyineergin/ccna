# 4.1 NTP
## Introduction
All devices have a **software clock** that keeps track of the current time. In Cisco IOS, the software clock can be viewed using the `show clock` command. The `show clock detail` command also displays the source of the software clock's time.
- The software clock can be manually set using the `clock set <time> <day> <month> <year>` command.
- The `clock read-calendar` command synchronizes the clock with the calendar's time.

A device may also have a **hardware clock**, which is a separate, battery-backed time source. The **hardware clock can drift over time**, so it is not an ideal source of accurate time. Accurate time is important because it ensures that log timestamps are accurate, which is essential for troubleshooting.
- The hardware clock can be manually set using the `calendar set <time> <day> <month> <year>` command.
- The `clock update-calendar` command synchronizes the calendar with the clock's time.

The timezone can be manually set using the `clock timezone <tz> <hours-offset> [<minutes-offset>]` command.

Daylight saving time can be manually set using the `clock summer-time recurring <tz> <start-date> <end-date> [<offset>]` command.
## NTP (Network Time Protocol)
NTP is a networking protocol used to synchronize the clocks of computers and other devices over a network.
- Manually configuring the time on devices is not scalable. Additionally, **manually configured clocks will drift over time**, resulting in inaccurate time.
- NTP clients request the time from NTP servers.
- A device can be NTP server and an NTP client at the same time.
- NTP can provide time accuracy of within ~1 millisecond when the NTP server is on the same LAN, or within ~50 milliseconds when connecting to an NTP server over a WAN or the Internet.
- Some NTP servers are more accurate than others. The distance of an NTP server from the original **reference clock** is called its **stratum**.
- NTP uses **UDP port 123** to communicate.
- `ntp server <ip-addr> [prefer]` command configures the device to synchronize its time with the specified NTP server.
- `ntp update-calendar` command updates the hardware calendar with the time from the NTP-synchronized software clock.
- `ntp source <interface-id>` command specifies the source interface whose IP address is used for NTP packets sent by the device.
- `show ntp associations` command displays information about the NTP servers with which the device is synchronized.
- `show ntp status` command displays the overall status of NTP, including whether the device is synchronized and its current NTP stratum.
## Reference Clock
A reference clock is a highly accurate source of time that an NTP system uses as a **baseline for determining the correct time**.
- It is typically a **highly accurate time source**, such as an atomic clock or a GPS clock.
- Reference clocks are **stratum 0** within the NTP hierarchy.
- NTP servers directly connected to the reference clocks are **stratum 1**.
- Stratum 15 is the maximum. A stratum value above 15 is considered unreliable.
- Devices can also peer with other devices at the same stratum to improve the accuracy of their time. This is called **symmetric active** mode.
- An NTP client can synchronize with multiple NTP servers.
- NTP servers that obtain their time directly from reference clocks are also called **primary servers**.
- NTP servers which obtain their time from other NTP servers are called **secondary servers**. They operate in server mode and client mode at the same time.
## NTP Operating Modes
NTP has several **operating modes**, describing how NTP devices communicate and synchronize time.
- **Client**: Requests time from an NTP server.
- **Server**: Provides time to NTP clients.
	- `ntp master [<stratum>]` command configures the device to act as an NTP master and provide time to other NTP clients.
- **Symmetric Active**: Two NTP servers exchange time information and can synchronize with each other.
	- `ntp peer <ip-addr>` command configures the device to establish an NTP peer association with the specified device.
## NTP Authentication
NTP authentication is a mechanism used to verify that an NTP client is communicating with a trusted NTP server.
- It allows NTP clients to ensure that they synchronize only with the intended servers.
- `ntp authenticate` command enables NTP authentication.
- `ntp authentication-key <key-num> md5 <key>` command creates an NTP authentication key.
- `ntp trusted-key <key-num>` command defines an authentication key as trusted.
- `ntp server <ip-addr> key <key-num>` command configures the device to use the specified authentication key when synchronizing with the NTP server.
