# 4.9 QoS
## QoS (Quality of Service)
QoS is a set of techniques used to **manage and prioritize network traffic** so that important applications receive the bandwidth and performance they need.
- Voice and data traffic were carried over separate networks. Modern networks are typically converged networks, in which IP phones, video traffic, regular data traffic and other types of traffic share the same IP network.
- This enable cost savings as well as more advanced features for voice and video traffic, for example integrations with collaboration software. However, the different kinds of traffic now have to compete for bandwidth.
- QoS is a set of tools used by network devices to apply different treatment to different packets.
- QoS is used to manage the following characteristics of network traffic:
	1. Bandwidth: The overall capacity of the link, measured in bits per second.
		- QoS tools allow a certain amount of a link’s bandwidth to be reserved for specific types of traffic.
	2. **Delay**: The time it takes for data packets to travel from the source to the destination.
		- One-Way Delay: The time it takes for traffic to travel from the source to the destination.
		- Two-Way Delay: The time it takes for traffic to travel from the source to the destination and back.
	3. **Jitter**: The variation in one-way delay between packets sent by the same application.
		- IP phones have a **jitter buffer** to provide a fixed delay to audio packets.
	4. **Loss**: The number or percentage of data packets that fail to reach their destination.
		- It can be caused by faulty cables.
		- It can also be caused when a device's packet queues get full and the device starts discarding packets.
- The following standards are recommended for acceptable interactive audio quality:
	- One-Way Delay: 150ms or less.
	- Jitter: 30ms or less.
	- Loss: 1% or less.
## QoS Classification
QoS classification is the process of identifying and categorizing network traffic based on characteristics such as IP addresses, protocols and port numbers so that appropriate QoS policies can be applied.
- The purpose of QoS is to give certain kinds of network traffic priority over others during congestion.
- Classification organizes network traffic (packets) into **traffic classes (categories)**.
- Classification is fundamental to QoS. To prioritize certain types of traffic, they must first be identified.
- There are many methods of classifying traffic.
	- An ACL. Traffic which is permitted by the ACL will be given certain treatment, other traffic will not.
	- **NBAR (Network Based Application Recognition)** performs deep packet inspection, examining information beyond Layers 3 and 4 up to Layer 7 to identify specific types of traffic.
	- In the layer 2 and eayer 3 headers there are specific fields used for this purpose.
		- The **PCP (Priority Code Point)** field of the 802.1Q tag can be used to identify high or low priority traffic.
		- The **DSCP (Differentiated Services Code Point)** field of the IP header can also be used to identify high or low priority traffic.
### PCP (Priority Code Point)
A 3-bit field in an IEEE 802.1Q tag that identifies the priority of an Ethernet frame.
- It is also known as **class of service (CoS)**. Its use is defined by IEEE 802.1p.
- IP phones **mark** call signaling traffic used to establish calls as **PCP3** and actual voice traffic as **PCP5**.
- Because PCP is found in the 802.1Q tag, it can only be used over the following connections:
	- Trunk links.
	- Access links with a voice VLAN.

| PCP Value |     Traffic Type      |                               Description                                |
| :-------: | :-------------------: | :----------------------------------------------------------------------: |
|   **0**   | Best Effort (Default) |            Normal traffic that receives no special priority.             |
|     1     |      Background       |         Low-priority traffic, such as background data transfers.         |
|     2     |   Excellent Effort    |      Traffic that receives better service than background traffic.       |
|   **3**   | Critical Applications | Traffic from important applications that require preferential treatment. |
|   **4**   |         Video         |      Video traffic that benefits from controlled delay and jitter.       |
|   **5**   |         Voice         |            Voice traffic that requires low delay and jitter.             |
|     6     | Internetwork Control  |     Traffic used for network protocols and internetwork operations.      |
|     7     |    Network Control    |  Highest-priority traffic used for essential network control functions.  |
### IP ToS (Type of Service) Byte
The IP ToS byte is an 8-bit field in the IPv4 header that indicates how a packet should be handled by the network.
- **IPP (IP Precedence)** is the older mechanism that uses the first 3 bits of the ToS byte to indicate the priority level of an IP packet.
- In modern IPv4, ToS byte is primarily interpreted using **DSCP (Differentiated Services Code Point)** and **ECN (Explicit Congestion Notification)**.
#### IPP (IP Precedence)
Standard IPP markings are similar to PCP:
- IPP6 and IPP7 are reserved for network control traffic, such as OSPF messages between routers.
- Interactive voice traffic is marked as IPP5.
- Video traffic is marked as IPP4.
- Voice signaling traffic is marked as IPP3.
- IPP0 is used for best effort traffic.
#### DSCP (Differentiated Services Code Point)
DSCP is a 6-bit field in the IP ToS byte that classifies IP packets into different traffic classes to enable QoS.
- RFC 2474 defines the DSCP field and other **differentiated services (DiffServ)** RFCs elaborate on its use.
- With IPP updated to DSCP, new standard markings had to be decided upon:
	- **Default Forwarding (DF)**: Best effort traffic.
		- The DSCP marking for DF is 0 (000000).
	- **Expedited Forwarding (EF)**: Low delay, low loss and low jitter traffic. Suitable for voice, video and other realtime services.
		- The DSCP marking for EF is 46 (101110).
	- **Assured Forwarding (AF)**: A set of 12 standard values.
	- **Class Selector (CS)**: A set of 8 standard values. Provides backward compatibility with IPP.
##### Assured Forwarding (AF)
- AF defines four traffic classes. All packets in a class have the same priority.
- Within each class, there are three levels of **drop precedence**.
	- A higher class means the packet has a higher priority.
	- A higher drop precedence means the packet is more likely to be dropped during congestion.
- The formula for converting an AF value to a DSCP value is $8X \times 2Y$.

##### Class Selector (CS)
- CS defines eight DSCP values for backward compatibility with IPP.
- The three bits that were added for DSCP are set to 0 and the original IPP bits are used to make 8 values.
- The formula for converting an CS value to a DSCP value is $8 \times \text{'CS Value'}$.

### RFC 4594
RFC 4954 was developed with the help of Cisco to provide guidelines for classifying network traffic into different DiffServ classes and assigning appropriate forwarding behavior to support QoS.
- The RFC offers many specific recommendations, but a few key ones are:
	- Voice Traffic -> **EF**
	- Interactive Video -> **AF4Y**
	- Streaming Video -> **AF3Y**
	- High-priority Data -> **AF2Y**
	- Best Effort -> **DF**
## QoS Queuing
QoS queuing is a technique that stores network packets in queues when they arrive faster than a network device can forward them and determines the order in which they are transmitted.
- By default, queued messages will be forwarded in a **first-in, first-out (FIFO)** manner.
	- Messages will be sent in the order they are received.
- If the queue is full new packets will be dropped. This is called **tail drop**.
- Tail drop can lead to **TCP global synchronization**.
	- When the queue fills up and tail drop occurs, all TCP hosts sending traffic will reduce the rate at which they send traffic.
	- They will all then increase the rate at which they send traffic, which can lead to further congestion and packet loss. This process then repeats.
- A solution to prevent tail drop and TCP global synchronization is **random early detection (RED)**.
	- When the amount of traffic in the queue reaches a certain threshold, the device will start randomly dropping packets from select TCP flows.
	- The TCP flows that dropped packets will reduce the rate at which traffic is sent, helping to avoid global TCP synchronization.
	- In standard RED, all kinds of traffic are treated the same.
- An improved version, **weighted random early detection (WRED)**, allows packet drops to be controlled based on the traffic class.
- An essential part of QoS is the **use of multiple queues**.
	- This is where classification plays a role. The device can classify traffic based on various factors and place it in the appropriate queue.
	- However, a device can forward only one frame out of an interface at a time, so a scheduler determines which queue's traffic is forwarded next.
		- Prioritization allows the scheduler to give certain queues more priority than others.
	- A common scheduling method is **weighted round-robin**.
		- Round-robin: Packets are taken from each queue in turn, cyclically.
		- Weighted: More data is taken from higher-priority queues each time the scheduler reaches them.
		- **CBWFQ (Class-Based Weighted Fair Queuing)** is a popular scheduling method that uses weighted round-robin scheduling while guaranteeing each queue a certain percentage of the interface’s bandwidth during congestion.
		- Round-robin scheduling is not ideal for voice and video traffic because it can introduce delay and jitter, as even high-priority queues must wait their turn.
	- **LLQ (Low-Latency Queuing)** designates one or more queues as **strict priority** queues.
		- This means that if a queue contains traffic, the scheduler will always take the next packet from the strict priority queue until the queue is empty.
		- This is very effective for reducing the delay and jitter of voice and video traffic.
		- However, it has the downside of potentially starving other queues if there is always traffic in the strict priority queue.
			- **Policing** can limit the amount of traffic allowed in the strict priority queue so that it cannot consume all of the link’s bandwidth.

## QoS Shaping and Policing
Shaping and policing are used to control the rate of network traffic and help enforce QoS policies.
- There are situations in which it is desirable to limit the traffic rate to below the link’s maximum capacity.
- **Shaping** buffers traffic in a queue if the traffic rate goes over the configured rate.
- **Policing** drops traffic if the traffic rate goes over the configured rate.
	- Burst traffic above the configured rate is allowed for a short period.
	- This accommodates data applications that are typically bursty in nature. Instead of sending a constant stream of data, they send data in bursts.
	- The amount of burst traffic allowed is configurable.

## Trust Boundaries
The trust boundary of a network defines where devices trust or do not trust the QoS markings of received packets.
- If the markings are trusted, the device will forward the packet without changing the markings.
- If the markings are not trusted, the device will change the markings according to the configured policy.
- If an IP phone is connected to the switch port, it is recommended to move the trust boundary to the IP phones.
	- This is configured on the switch port connected to the IP phone.
