# 2.2 Network Redundancy
## Introduction
A **broadcast storm** or **broadcast radiation** is the accumulation of broadcast and multicast traffic on a network. It can consume sufficient network resources so as to render the network unable to transport normal traffic.

**MAC address flapping** occurs when a network switch repeatedly learns the same MAC address on different interfaces within a short period.
## STP (Spanning Tree Protocol)
STP is a layer 2 protocol that **builds a loop-free logical topology for Ethernet networks**. The basic function of STP is to **prevent bridge loops and the broadcast storms** that results from them.
- Originally standardized as **IEEE 802.1D**.
- Prevents loops by **placing redundant ports in a blocking state**, essentially disabling them for normal traffic.
- **Blocked interfaces act as a backups** that can enter a forwarding state if an active (currently forwarding) interface fails.
- Interfaces in **forwarding state** behave normally.  They send and receive all normal traffic.
- Interfaces in **blocking state** only send and receive STP messages called **BPDUs (Bridge Protocol Data Unit)**.
- STP BPDUs use the destination MAC address ***0180.C200.0000***.
- By selecting which ports are forwarding and which ports are blocking, STP **creates a single path to/from each point** in the network.
### STP Port States
STP (IEEE 802.1D) has **five port states**.
#### Disabled
The port is **administratively shut down or otherwise unavailable**.
- Does not send or receive BPDUs.
- Does not forward traffic.
- Does not learn MAC addresses.
#### Blocking
The port is **not allowed to forward normal traffic**.
- Receives BPDUs.
- Does not send/receive normal traffic.
- Does not learn MAC addresses.
- Helps prevent layer 2 loops.
- Non-designated ports are in blocking state.
#### Listening
The port is **preparing to participate in the spanning tree**.
- Receives and sends BPDUs.
- Does not send/receive normal traffic.
- Does not learn MAC addresses.
- Determines whether the port should become a root port or designated port.
- The listening state is **15 seconds by default**. This is determined by **forward delay** timer.
#### Learning
The port is **preparing to forward traffic**.
- Receives and sends BPDUs.
- Does not send/receive normal traffic **yet**.
- **Learns MAC addresses**.
- The learning state is **15 seconds by default**. This is determined by **forward delay** timer.
#### Forwarding
The port is **fully operational**.
- Receives and sends BPDUs.
- **Forwards normal traffic**.
- Learns MAC addresses.
- Root and designated ports are in forwarding state.

| STP Port State | Send/Receive BPDUs | Frame Forwarding<br>(Normal Traffic) | MAC Address Learning | Stable/Transitional |
| :------------: | :----------------: | :----------------------------------: | :------------------: | :-----------------: |
|  **Disabled**  |        ❌/❌         |                  ❌                   |          ❌           |       Stable        |
|  **Blocking**  |        ❌/✅         |                  ❌                   |          ❌           |       Stable        |

### STP Timers
STP (IEEE 802.1D) uses **three main timers** to control how quickly switches **exchange BPDUs and transition between port states**.
#### Hello
The hello timer **determines how often the root bridge sends BPDUs**.
- BPDUs are sent every **2 seconds** by default.
- It is configured on the root bridge and its value is propagated through the STP topology.
- Switches **do not forward BPDUs out of their root or non-designated ports**. They **only forward them out of their designated ports**.
#### Forward Delay
The forward delay timer **determines how long a port stays in the listening and learning states** before moving to the next state.
- Default → 15 Seconds
- Listening → 15 Seconds
- Learning → 15 Seconds
- Total → 30 Seconds
#### Max Age
The max age timer **determines how long a switch keeps information received in a BPDU** before considering that information expired.
- **20 seconds** by default.
- If a switch does not receive a valid BPDU **within the max age period**, it **considers the path to the root bridge potentially unavailable** and begins recalculating the spanning tree.
### Spanning Tree Optional Features (STP Toolkit)
The STP Toolkit is a collection of optional STP features that **improve STP stability, security, and convergence**.
#### PortFast
PortFast allows an access port to **immediately transition to the forwarding state**, bypassing the normal listening and learning states.
- Intended for ports connected to **end hosts**.
- Should generally not be used on switch-to-switch links.
- A PortFast-enabled port **still sends BPDUs** and **will operate like a regular STP port if it receives BPDUs**.
- Command `spanning-tree portfast default` enables PortFast on all **access ports**.
#### BPDU Guard
BPDU Guard protects ports that should not receive BPDUs, typically **PortFast-enabled access ports**.
- If a BPDU is received, the port is placed into an **err-disabled state**.
- Helps prevent an unauthorized switch from affecting the STP topology.
- A BPDU Guard-enabled port **continues to send BPDUs**.
- Command `spanning-tree portfast bpduguard default` enables BPDU Guard on all **PortFast-enabled interfaces**.
#### BPDU Filter
BPDU Filter prevents a port from **sending and/or receiving BPDUs**.
- Should be used carefully because it can effectively disable STP on the port.
- Can be used with PortFast in specific situations.
- A BPDU Filter-enabled port **will not send BPDUs** and **will ignore any BPDUs it receives** when BPDU Filter is **configured at the per-port level**. This **disables STP** on the port.
- When BPDU Filter is **enabled globally**, the port will not send BPDUs. If the port receives a BPDU, **PortFast and BPDU Filter are disabled**, and the port **operates as a normal STP port**.
- Command `spanning-tree portfast bpdufilter default` enables BPDU Filter on all **PortFast-enabled interfaces**.
#### Root Guard
Root Guard prevents a port from becoming a path to a new root bridge.
- If a superior BPDU is received, the port is placed into a **root-inconsistent state**.
- The port does not forward traffic until the superior BPDUs stop.
- Prevents an unexpected switch from becoming root bridge.
- Provides a way to **enforce the root bridge** placement in the network.
- Meant to **prevent designated ports from becoming root ports**.
#### Loop Guard
Loop Guard protects against layer 2 loops caused by a **unidirectional link failure**.
- If a port that should be receiving BPDUs stops receiving them, loop guard places the port into a **loop-inconsistent state** instead of allowing it to become designated/forwarding.
- Prevents a blocked redundant link from incorrectly transitioning to forwarding.
- Should be enabled on root and non-designated ports (ports that are supposed to receive BPUDs).
- Meant to **prevent root and non-designated ports from becoming designated ports**.
- Command `spanning-tree loopguard default` enables Loop Guard on all interfaces.
## BPDU (Bridge Protocol Data Unit)
A BPDU is a layer 2 control frame used by STP-enabled switches to **exchange information about the network topology**.
- Switches use BPDUs to identify layer 2 loops and build a loop-free topology.
- BPDUs contain information such as the **bridge ID** and **path cost**, which STP uses to determine the **best paths** and select the **root bridge**.
- BPDUs allow switches to determine which ports should be in a **forwarding** state and which should be **blocking**.
- Switches **send and receive BPDUs on their STP-enabled interfaces**.
- If a switch receives a **Hello BPDU** on an interface, if knows that the interface is connected to another switch.
### Bridge ID
The bridge ID is an identifier used by STP to **uniquely identify a switch and determine which switch becomes the root bridge**. The switch with the **lowest priority** becomes the root bridge.
- Consists of bridge priority, VLAN ID and MAC address.
	- **Bridge Priority**: A configurable value used to influence which switch becomes the root bridge. The default is 32768*.
	- **VLAN ID**: Identifies the VLAN for which the STP instance operates.
	- **MAC Address**: The switch's MAC address, used as a tie-breaker if two switches have the same priority.

>\*: In the default VLAN1, the default bridge priority is 32769 (32768 + 1) due to the addition of the extended system ID.

### Root Bridge
The root bridge is the switch that STP selects as the **central reference point for the layer 2 topology**.
- STP elects the root bridge by comparing the bridge IDs of all participating switches. The **switch with the lowest bridge ID becomes the root bridge**.
- The root bridge **has no root port** because it **is the destination/reference point** for all other switches.
- All ports on the root bridge are **designated ports (forwarding state)**.
- Every **non-root switch selects one root port**, which provides its best path toward the root bridge. Root ports are in forwarding state.
- The root bridge helps STP determine which paths should **forward traffic** and which redundant paths should be **blocked**.
### Path Cost
The path cost is the value STP uses to determine the **best path from a switch to the root bridge**. STP generally prefers paths with the **lowest total path cost**.
- Each port has an associated **STP cost**, based primarily on the interface's bandwidth.
- A switch **adds the costs of all ports along a path to calculate the total path cost**.
- On non-root switches, the port providing the **lowest-cost path to the root bridge is selected as the root port**.

|  Speed   | STP Cost |
| :------: | :------: |
| 10 Mbps  |   100    |
| 100 Mpbs |    19    |
|  1 Gbps  |    4     |
| 10 Gbps  |    2     |
### Root Port
The root port is the port on a **non-root switch** that provides the **best path to the root bridge**.
- Every **non-root switch has exactly one root port**.
- The **root bridge does not have a root port**.
- The root port is placed in the **forwarding state**.
- STP uses **root port selection** to determine how each non-root switch reaches the root bridge.

**Root Port Selection**:
1. Lower Root Path Cost
2. If Tied → **Lowest Sender/Neighbor Bridge ID**
3. If Still Tied → **Lowest Sender/Neighbor Port ID**

Each remaining collision domain will select **one interface to be a designated port**. The other port in the collision domain will be a **non-designated (blocking) port**.

**Designated Port Selection**:
1. Interface on the switch with the lowest root path cost.
2. If Tied → Interface on the switch with the lowest bridge ID.

### Port ID
The port ID is an identifier that STP uses to **identify a specific switch port**. It is important when STP needs a **tie-breaker** between otherwise equal paths or ports.
- Consists of port priority and port number.
	- **Port Priority**: A configurable value used to influence which port is preferred. The default is 128.
	- **Port Number**: Identifies the physical/logical port on the switch.
## STP Load Balancing
STP load balancing is the practice of using different STP topologies for different VLANs so that **traffic from different VLANs can use different forwarding paths**.
- STP blocks redundant paths to prevent layer 2 loops.
- Without load balancing, the same path may be used for all VLANs, **leaving other links underutilized**.
- By configuring different root bridges for different VLANs, **different VLANs can use different paths**.
- This **allows multiple links to actively forward traffic**, while still maintaining a loop-free topology.
