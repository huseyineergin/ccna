# 2.5 Wireless Architectures
## 802.11 Frame Structure
802.11 frame structure is the format used by Wi-Fi devices to transmit data over a wireless network.
- Depending on the 802.11 version and the message type, some of the fields might not be present in the frame.

Generic 802.11 frame consists of:
- **Frame Control**: Provides information about the frame, such as its type and subtype.
- **Duration/ID**: Depending on the frame type, this field indicates:
	- The time, in microseconds, for which the channel is reserved for frame transmission.
	- The association identifier (AID).
- **Addresses**: Up to four addresses can be present in an 802.11 frame. Their presence and order depend on the frame type.
	- **Destination Address (DA)**: The final recipient of the frame.
	- **Source Address (SA)**: The original sender of the frame.
	- **Receiver Address (RA)**: The immediate recipient of the frame.
	- **Transmitter Address (TA)**: The immediate sender of the frame.
- **Sequence Control**: Used to reassemble fragmented frames and eliminate duplicates.
- **QoS Control**: Used to prioritize traffic based on quality of service (QoS).
- **HT (High-Throughput) Control**: Introduced in 802.11n to support high-throughput operations.
- **Frame Body**: Contains the payload.
- **FCS (Frame Check Sequence)**: Used for error detection, similar to the FCS field in an Ethernet frame.

## 802.11 Association Process
The 802.11 association process is the procedure by which a wireless device establishes a logical connection with an access point (AP) after discovering the wireless network.
- Access points bridge traffic between wireless devices (stations) and other devices on the network. Before a wireless device can send traffic through an AP, it must be in the appropriate connection state.
- There are three 802.11 connection states:
	- **Unauthenticated/Unassociated**
	- **Authenticated/Unassociated**
	- **Authenticated/Associated**
- The station must be authenticated and associated with the AP to send traffic through it.
- There are two ways a wireless device can scan for a BSS:
	- **Active Scanning**: The wireless device sends probe requests and listens for a probe response from an AP.
	- **Passive Scanning**: The wireless device listens for beacon messages from an AP. Beacon messages are sent periodically by APs to advertise the BSS.

## 802.11 Frame Types
802.11 frame types define the purpose of a wireless frame and how a wireless device or access point processes it.
- There are three 802.11 frame types:
	- **Management**: Used to manage the BSS.
		- Beacon
		- Probe Reqeust, Probe Response
		- Authentication
		- Association Request, Association Response
	- **Control**: Used to control access to the medium (radio frequency) and assist in the delivery of management and data frames.
		- RTS (Request to Send)
		- CTS (Clear to Send)
		- ACK (Acknowledgment)
	- **Data**: Used to send actual data packets.
## Autonomous Access Points
Autonomous APs can operate and manage their Wi-Fi functions **independently**, without requiring a centralized wireless LAN controller (WLC).
- Autonomous APs are configured **individually**.
	- They can be configured through a console connection, Telnet/SSH or an HTTP/HTTPS web interface.
- There is **no central monitoring or management** of APs.
- Autonomous APs connect to the wired network with a **trunk link**.
	- This allows management traffic for remotely accessing APs and other network devices, such as switches, to be carried over a separate VLAN.
- Data traffic from wireless clients follows a direct path to the wired network or to other wireless clients associated with the same AP.
- Each VLAN has to stretch across the entire network. This is considered bad practice.
	- It creates large broadcast domains.
	- STP may block redundant links.
	- Adding or removing VLANs requires significant manual effort.
- Autonomous APs are suitable for small networks but are generally impractical for medium to large networks.
- Autonomous APs can also operate in repeater, outdoor bridge and workgroup bridge modes.
## Lightweight Access Points
Lightweight APs provide Wi-Fi connectivity but rely on a central **wireless LAN controller (WLC)** to manage and configure them.
- The functions of an AP can be split between the AP and a WLC.
	- Lightweight APs handle real-time operations, such as transmitting and receiving RF traffic, encrypting and decrypting traffic and sending beacons and probes.
	- A WLC handles functions such as RF management, security and QoS management, client authentication and client association and roaming management.
	- This is called **split-MAC architecture**.
- The WLC is also used to centrally configure lightweight APs.
	- The WLC can be located in the same subnet/VLAN as the lightweight APs it manages or in a different subnet/VLAN.
- The WLC and lightweight APs authenticate each other using digital certificates installed on each device.
	- This ensures that only authorized APs can join the network.
- The WLC and lightweight APs use a protocol called **CAPWAP (Control and Provisioning of Wireless Access Points)** to communicate.
	- - CAPWAP is based on an older protocol called **LWAPP (Lightweight Access Point Protocol)**.
- Two tunnels are created between each AP and the WLC:
	- **Control Tunnel**: This tunnel is used to configure the APs and control and manage their operations. All traffic in this tunnel is encrypted by default. It uses **UDP port 5246**.
	- **Data Tunnel**: All traffic from wireless clients is sent through this tunnel to the WLC rather than directly to the wired network. It uses **UDP port 5247**.
		- Traffic in this tunnel is not encrypted by default, but encryption can be enabled using **DTLS (Datagram Transport Layer Security)**.
	- Because all wireless client traffic is tunneled to the WLC, APs connect to switch **access ports**.
- There are several key benefits to split-MAC architecture:
	- **Scalability**: Using a WLC makes it much easier to build and support a network with thousands of APs.
	- **Dynamic Channel Assignment**: The WLC can automatically select the channel each AP should use.
	- **Transmit Power Optimization**: The WLC can automatically set the appropriate transmit power for each AP.
	- **Self-Healing Wireless Coverage**: When an AP stops functioning, the WLC can increase the transmit power of nearby APs to prevent coverage gaps.
	- **Seamless Roaming**: Clients can roam between APs with no noticeable delay.
	- **Client Load Balancing**: If a client is within range of two APs, the WLC can associate it with the less-loaded AP to balance the load across APs.
	- **Security/QoS Management**: Centrally managing security and QoS policies ensures consistency across the network.
### Lightweight AP Operational Modes
**Local**: The default mode. The AP provides one or more BSSs for clients to associate with.

**FlexConnect**: Like local mode, but allows the AP to locally switch traffic between the wired and wireless networks if connectivity to the WLC is lost.

**Sniffer**: The AP does not provide a BSS. It captures 802.11 frames and sends them to a device running software such as Wireshark.

**Monitor**: The AP does not provide a BSS. It monitors 802.11 frames to detect rogue devices and can send deauthentication messages to disconnect clients from rogue APs.

**Rogue Detector**: The AP does not use its radio. It monitors wired network traffic, correlating ARP messages with rogue device MAC addresses supplied by the WLC to identify rogue devices.

**SE-Connect (Spectrum Expert Connect)**: The AP does not provide a BSS. It performs RF spectrum analysis across channels and sends the data to software such as Cisco Spectrum Expert for analysis.

**Bridge/Mesh**: The AP acts as a dedicated bridge between sites, potentially over long distances. Multiple APs can form a wireless mesh.

**Flex + Bridge**: Combines FlexConnect functionality with Bridge/Mesh mode, allowing the AP to locally forward traffic if connectivity to the WLC is lost.
### WLC Deployments
In a split-MAC architecture, there are four main WLC deployment models.

**Unified**: The WLC is a hardware appliance in a central location of the network.
- A unified WLC can support up to approximately 6,000 APs.

**Cloud-Based**: The WLC runs as a VM on a server, usually in a private cloud within a data center. This is different from cloud-based AP architecture.
- A cloud-based WLC can support up to approximately 3,000 APs.

**Embedded**: The WLC is integrated into a switch.
- An embedded WLC can support up to approximately 200 APs.

**Mobility Express**: The WLC is integrated into an AP.
- A Mobility Express WLC can support up to approximately 100 APs.

## Cloud-Based Access Points
Cloud-based APs provide Wi-Fi connectivity to devices, while their configuration and management are handled through a cloud platform over the internet.
- Cloud-based AP architecture falls between autonomous AP architecture and split-MAC architecture.
	- They function like autonomous APs but are centrally managed in the cloud.
- **Cisco Meraki** is a popular cloud-based Wi-Fi solution.
	- The Meraki dashboard can be used to configure APs, monitor the network and generate performance reports.
	- Meraki also determines which channel each AP should use and its transmit power.
- Data traffic is not sent to the cloud. It is forwarded directly to the wired network, as with autonomous APs. Only management and control traffic is sent to the cloud.
