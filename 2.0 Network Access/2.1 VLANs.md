# 2.1 VLANs
## Introduction
A **local area network (LAN)** is a network in which devices belong to the same **broadcast domain**.

A **broadcast domain** is a group of devices that can receive a **broadcast frame** sent by any device within that domain.

![Broadcast Domains Network Topology](../Attachments/Images/Broadcast%20D.%20Network%20Topology.png)

A **virtual local area network (VLAN)** is a **logical segment** within a physical network.
- Divides a physical switch into multiple **separate layer 2 networks**.
- Is configured on a **per-interface basis** on switches.
- Each VLAN is a **separate broadcast domain**.
- Used to **improve performance and security**, as well as provide **better organization**.
- Switches do not forward traffic between hosts in different VLANs*.

>\*: Layer 3 switches can **perform inter-VLAN routing**.
## Types of Switch Port
A switch port is a physical interface on a network switch that is used to **connect the switch to another network device**, such as a PC, server, router or another switch.
### Access Port
An access port is a switchport that **belongs to one VLAN**.
- Used mainly to **connect end hosts**.
- Frames sent to/from the end device are generally **untagged**.
### Trunk Port
A trunk port **carries traffic for multiple VLANs**.
- Commonly **used between switches**.
- Can also be used between a switch and a router.
- One physical link can carry traffic from many VLANs.
- VLAN information is carried using **802.1Q tags**.
## VLAN Tagging
VLAN tagging is the process of adding a tag to an Ethernet frame to **identify which VLAN the frame belongs to**. There are two main tagging (trunking) protocols.
### ISL (Inter-Switch Link)
ISL is a link layer protocol that **maintains VLAN information in Ethernet frames** as traffic flows between switches and routers, or switches and switches.
- It is an old Cisco proprietary protocol created before the industry standard IEEE 802.1Q.
- It is deprecated and modern Cisco devices don't support it.
### IEEE 802.1Q
802.1Q is the standard used to **identify and carry VLAN information in Ethernet frames**, primarily over trunk links.
- Adds a **4-byte** tag to an Ethernet frame **between the source address and EtherType fields**.
#### Tag Structure
![802.1Q Tag Structure](../Attachments/Images/802.1Q%20Tag%20Structure.png)
##### TPID (Tag Protocol Identifier)
A **16-bit** field set to a **value of 0x8100** in order to **identify the frame as an IEEE 802.1Q-tagged frame**. This field is **located at the same position as the EtherType field in untagged frames**, and is thus **used to distinguish the frame from untagged frames**.
##### TCI (Tag Control Information)
A **16-bit** field containing the following sub-fields:

**PCP (Priority Code Point)**
A **3-bit** field which refers to the IEEE 802.1p class of service (CoS) and **maps to the frame priority level**.
- Used for **traffic prioritization**.
- Provides **8 priority levels (0–7)**.
- Higher value generally indicates higher priority.

**DEI (Drop Eligible Indicator)**
A **1-bit** field. Used separately or in conjunction with PCP to indicate frames eligible to be dropped if the network is congested.

**VID (VLAN Identifier)**
A **12-bit** field specifying the VLAN to which the frame belongs.
- Supports **VLAN IDs from 0 to 4095** (4094 usable VLAN IDs).
- VLANs 0 and 4095 are reserved and can't be used.
- VLANs 1-1005 are normal VLANs.
- VLANs 1006-4094 are extended VLANs. Some older devices might not support extended range.
#### Native VLAN
The native VLAN is the VLAN **assigned to a trunk port whose frames are sent without an 802.1Q tag**.
- The switch **does not add an 802.1Q tag to the frames** belonging to the native VLAN.
- When a switch receives an **untagged frame on a trunk port**, it **assumes the frame belongs to the native VLAN**. Therefore, it is important that the **native VLAN matches on both ends of the trunk**.
- The default native VLAN on Cisco switches is VLAN1.
## ROAS (Router on a Stick)
ROAS is a method of **routing between multiple VLANs using a single physical router interface**.
- Uses **one physical router interface**.
- The router interface is divided into **multiple subinterfaces**.
- Each subinterface is associated with a **different VLAN**.
- Each subinterface has an IP address that serves as the **default gateway** for that VLAN.
- The switch interface is configured as trunk.

![ROAS Network Topology](../Attachments/Images/ROAS%20Network%20Topology.png)
## SVI (Switch Virtual Interface)
A switch virtual interface or routed VLAN interface (RVI) is a **virtual network interface that represents a logical layer 3 interface** on a multilayer network switch.
- Does not correspond to a physical switch port.
- It **can be assigned an IP address** to provide layer 3 connectivity.
- Can act as the **default gateway** for devices in its VLAN.
- Commonly used to **perform inter-VLAN routing**.
## DTP (Dynamic Trunking Protocol)
DTP is a Cisco proprietary layer 2 protocol used by switches to **automatically negotiate whether a switch port should become a trunk link**.
- It is enabled by default on all Cisco switch interfaces.
- It should be disabled on all switchport for security purposes.
- It **will not form a trunk link with a router, PC, etc**. The switchport **will be in access mode**.
- DTP negotiation can be disabled with `swithport nonegotiate` command. An access port configured with `switchport mode access` also disables it.
- A switchport in **dynamic desirable mode will actively try to form a trunk link**. It will form a trunk link with a switchport in the following modes:
	- `switchport mode trunk`
	- `switchport mode dynamic desirable`
	- `switchport mode dynamic auto`
- A switchport **dynamic auto mode will not actively try to form a trunk link**, however it **will form a trunk link if the switch connected to it is actively trying to form a trunk link**. It will form a trunk link with a switchport in the following modes:
	- `switchport mode trunk`
	- `switchport mode dynamic desirable`
- Switches that support both 802.1Q and ISL trunk encapsulations can use DTP to negotiate the encapsulation they use. This negotiation is enabled by default, as the default trunk encapsulation mode is `switchport trunk encapsulation negotiate`.
- **ISL is favored over 802.1Q**, so if both switches support ISL, it will be selected.
- DTP frames are **sent in VLAN1 when using ISL**, or **in the native VLAN when using 802.1Q**.

|  Administrative Mode  | Trunk | Dynamic Desirable | Access | Dynamic Auto |
| :-------------------: | :---: | :---------------: | :----: | :----------: |
|       **Trunk**       | Trunk |       Trunk       |   X    |    Trunk     |
| **Dynamic Desirable** | Trunk |       Trunk       | Access |    Trunk     |

## VTP (VLAN Trunking Protocol)
VTP is a Cisco proprietary layer 2 protocol that **propagates the definition of VLANs on the whole LAN**. To do this, **VTP carries VLAN information to all the switches in a VTP domain**.
- VTP **allows VLANs to be configured on a central VTP server switch**, while other **switches operating as VTP clients synchronize their VLAN databases with the server**.
- It is designed for large networks with many VLANs, reducing the need to configure each VLAN individually on every switch.
- It is rarely used, and it is **not recommended to use it**.
- There are **three versions of VTP**, namely version 1, version 2 and version 3.
- There are **three VTP modes**, namely server, client and transparent.
- Cisco switches operate in VTP server mode by default.

**VTP Servers**:
- Can add, modify and delete VLANs.
- Store the VLAN database in non-volatile RAM (NVRAM). This means **VLAN database is saved even if the switch is turned off or reloaded**.
- Will **increase the revision number** every time a VLAN is added, modified or deleted. Revision number is **used to determine the newest version of the VLAN database**.
- Will advertise the latest version of the VLAN database on trunk interfaces, and the VTP clients will synchronize their VLAN databases to it.
- **Also function as VTP clients**. Therefore, a VTP server **will synchronize to another VTP server with a higher revision number**.

**VTP Clients**:
- Cannot add, modify and delete VLANs.
- Do not store VLAN database in NVRAM. **(in VTPv3, they do)**
- Will **synchronize their VLAN database to the server with the highest revision number in their VTP domain**.
- Will **advertise their VLAN database**, and **forward VTP advertisements to other clients over their trunk ports**.

**VTP Transparent**:
- Does not participate in the VTP domain and does not synchronize its VLAN database.
- Maintains its own VLAN database in NVRAM. 
- Can add, modify and delete VLANs, but these changes are not advertised to other switches.
- Will forward VTP advertisements that belong to the same VTP domain.
