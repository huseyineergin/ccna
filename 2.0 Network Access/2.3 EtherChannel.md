# 2.3 EtherChannel
## Introduction
**Oversubscription** occurs when the total bandwidth of interfaces connected to end hosts is greater than the bandwidth available toward the distribution layer. Too much of it can cause **congestion**.

**EtherChannel** groups multiple physical interfaces into one logical link called a **port-channel**.
- STP will treat this group as a single interface.
- Traffic using the EtherChannel will be load balanced amoung the physical interfaces in the group. An algorithm is used to determine which traffic will use which physical interface.
## EtherChannel Types
EtherChannel can operate at either layer 2 or layer 3.
### Layer 2 EtherChannel
A layer 2 EtherChannel forwards Ethernet frames and operates as a **switchport**.
- Member interfaces are configured as access or trunk ports.
- Can carry VLAN traffic.
### Layer 3 EtherChannel
A layer 3 EtherChannel forwards IP packets and operates as a **routed interface**.
- Member interfaces operate as routed ports.
- The port-channel interface has an IP address.
## EtherChannel Protocols
EtherChannel can be formed using **LACP**, **PAgP**, or **static configuration**. Up to 8 interfaces can be formed into a single EtherChannel*.
>\*: LACP allows up to 16 interfaces, but only 8 can be active at a time. The other 8 will remain in standby mode, waiting for an active interface to fail.
### LACP (Link Aggregation Control Protocol)
LACP is an IEEE standard protocol used to **dynamically negotiate** an EtherChannel.
- Standardized as **IEEE 802.3ad**.
- Uses **active** and **passive** modes.
- A port in active mode actively attempts to form an EtherChannel.
- A port in passive mode waits for LACP messages from the other side.
### PAgP (Port Aggregation Protocol)
PAgP is a **Cisco proprietary** protocol used to **dynamically negotiate** an EtherChannel.
- Cisco proprietary.
- Uses **desirable** and **auto** modes.
- A port in desirable mode actively attempts to form an EtherChannel.
- A port in auto mode waits for PAgP messages from the other side.
### Static EtherChannel
A static EtherChannel is configured **without using a negotiation protocol**.
- Interfaces are statically configured to form an EtherChannel.
-  No LACP or PAgP negotiation occurs.
- Uses mode **on**.
- Both sides must use mode **on** to form an EtherChannel.
- A port in **on** mode can't form an EtherChannel with a port in **active** or **desirable** mode.
## EtherChannel Load Balancing
EtherChannel load balancing **determines how traffic is distributed** across the physical links within an EtherChannel.
- EtherChannel load balances based on **flows**.
- A flow is a communication between two nodes in the network.
- Frames in the same flow will be forwarded using the same physical interface.
- This prevents packets from arriving out of order.
### Load Balancing Methods
Switches can use different values as inputs to the hashing algorithm.
- Source MAC address.
- Destination MAC address.
- Source and destination MAC address.
- Source IP address.
- Destination IP address.
- Source and destionation IP address.
- Depending on the platform, **layer 4 ports** can also be used.
## EtherChannel Requirements
The physical interfaces that form an EtherChannel must have **compatible configurations**.
- Same speed and duplex.
- Same switchport mode.
- Same access VLAN, if configured as access ports.
- Same native VLAN, if configured as trunk ports.
- Same allowed VLANs, if configured as trunk ports.
