# 3.4 IPv6 Addressing
## Introduction
An IPv6 address is **128 bits** long. An IPv6 address is written as **8 groups of 4 hexadecimal digits**, separated by colons.

IPv6 addresses can be **shortened**.
- Leading zeros in a group can be removed:
	- *2001:**0**DB8:**000**A:**00**1B:20A1:**00**20:**00**80:34BD* -> *2001:DB8:A:1B:20A1:20:80:34DB*
- Consecutive groups of zeros can be replaced with a double colon:
	- *2001:0DB8:**0000**:**0000**:**0000**:**0000**:0080:34BD* -> *2001:0DB8::0080:34BD*
- Both methods can be combines:
	- *2001:**0**DB8:**0000**:**0000**:**0000**:**0000**:**00**80:34BD* -> *2001:DB8::80:34BD*

**Modified EUI-64**\* is a method used in IPv6 to create the **64-bit interface ID** portion of an IPv6 address from a device's **MAC address**.
1. Divide the MAC address in half.
2. Insert *FF:FE* in the middle.
3. Invert the seventh** bit.

>\*: EUI stands for Extended Unique Identifier.

>\*\*: Seventh bit is called universal/local (U/L) bit. It indicates whether the address is universally administered address (UAA) or locally administered address (LAA).

## Finding IPv6 Prefix
- Typically, an enterprise requesting IPv6 addresses from their ISP will receive a **/48** block.
- Typically, IPv6 subnets use **/64** prefix.
- That means there are 16 bits available for creating subnets.
- The remaining 64 bits can be used for hosts.

## IPv6 Address Types
IPv6 addresses are commonly classified by **scope** and **delivery type**. Unlike IPv4, IPv6 **does not use broadcast**. Multicast replaces most broadcast functions.
### Unicast
A unicast address **identifies one interface**. A packet sent to a unicast address is delivered to one destination.
#### Global Unicast
Global unicast addresses (GUAs) are IPv6 addresses that can be **routed across networks**, including the public Internet.
- They are roughly equivalent to a **public IPv4 addresses**.
- They must be registered to be used. Since they are public addresses, they are expected to be globally unique.
- The range of addresses to be used as GUAs was originally defined as *2000::/3*.
	- This covers addresses from *2000::* to *3FFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF*.
- It is now defined as all addresses that aren't reserved for other purposes.
	- *2001:db8::/32* is reserved for documentation/examples, not real Internet use.
#### Unique Local
Unique local addresses (ULAs) are IPv6 addresses intended for **private/internal networks**. They are not intended to be routed across the public Internet.
- They are similar in purpose to **private IPv4 addresses** such as *10.0.0.0/8* or *192.168.0.0/16*.
- They don't need to be registered to be used. They can be used freely within internal networks and don't need to be globally unique*.
- The address block of ULAs is *FC00::/7*.
	- This covers addresses from *FC00::* to *FDFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF*.
	- However, a later update requires the eighth bit to be set to 1, so the first two hexadecimal digits must be **FD**.

>\*: The global ID should be unique so that addresses don't overlap companies connect their networks.

![Unique Local Address](../Attachments/Images/Unique%20Local%20Address.png)
#### Link Local
Link-local addresses (LLAs) are IPv6 addresses used for communication only on the **local network link**.
- They are **automatically generated on IPv6-enabled interfaces**.
- Link-local addresses are **used for communication within a single link**. Routers won't route packets with a link-local IPv6 destination address.
- The address block of LLAs is *FE80::/10*.
	- This covers addresses from *FE80::* to *FEBF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF*.
	- However, the standard states the first 64 bits of a LLA consist of the 10-bit prefix 1111111010 followed by 54 zero bits. Therefore, LLAs always begin with **FE80**.
	- The remaining 64 bits form the interface ID. It is generated using EUI-64 rules.
- Common use cases for LLAs are:
	- Routing protocol peerings. OSPFv3 uses LLAs for neighbor adjacencies.
	- Next hop addresses for static routes.
	- **Neighbor Discovery Protocol (NDP)** uses LLAs to function.
### Multicast
A multicast address **identifies a group of interfaces**. A packet sent to it is delivered to all interested members of the group.
- Multicast is **one-to-many**.
- IPv6 doesn't use broadcast. Multicast is used when a message needs to reach all hosts.
- The address block of multicast addresses is *FF00::/8*.
	- This covers addresses from *FF00::* to *FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF*.

|      Purpose      | IPv6 Address | IPv4 Address |
| :---------------: | :----------: | :----------: |
|     All Hosts     |   FF02::1    |  224.0.0.1   |
|    All Routers    |   FF02::2    |  224.0.0.2   |
| All OSPF Routers  |   FF02::5    |  224.0.0.5   |
| All OSPF DRs/BDRs |   FF02::6    |  224.0.0.6   |
|  All RIP Routers  |   FF02::9    |  224.0.0.9   |
| All EIGRP Routers |    FF02:A    |  224.0.0.10  |
#### Multicast Scopes
IPv6 defines multiple multicast scopes which determine how far the multicast traffic can travel.
- **Interface-local (FF01)**: The packet doesn't leave the **local interface**. It can be used to send traffic to a service within the local device.
- **Link-local (FF02)**: The packet remains in the **local subnet**. Routers will not route packet between subnets.
- **Site-local (FF05)**: The packet can be forwarded by routers. However, it should be limited to a **single physical location** and not forwarded over a WAN.
- **Organization-local (FF08)**: Wider in scope than site-local. It can span multiple sites within an organization.
- **Global (FF0E)**: It has **no boundaries** and can be routed over the Internet.

![IPv6 Multicast Scopes](../Attachments/Images/IPv6%20Multicast%20Scopes.png)
### Anycast
An anycast address is **assigned to multiple interfaces**, but traffic is delivered to one of them. Normally the topologically nearest one according to routing.
- Anycast is **one-to-one-of-many**.
- Multiple routers are configured with the same IPv6 address.
	- They use a routing protocol to advertise the address.
	- When hosts send packets to that destination address, routers will forward them to the **nearest**\* router configured with that address.
- There is no specific range for anycast addresses. It uses an address from the unicast address space.

>\* Nearest refers to the smallest routing protocol metric.

### Others
*::* -> Unspecified IPv6 address.
- Equivalent to *0.0.0.0* in IPv4.
- IPv6 default routes are configured to *::/0*.
- A host uses it when it does not have an IPv6 address.

*::1* -> Loopback address.
- Equivalent to *127.0.0.1* in IPv4.
- Messages sent to this address are processed within the local device.
## IPv6 Header
The IPv6 header is the fixed part of an IPv6 packet. It contains information needed to deliver the packet from the source to the destination. It consists of 8 fields.
- Unlike IPv4, the IPv6 header has a **fixed size of 40 bytes**.
### Version
It is the first header field in an IP packet. For IPv4, this is always equal to 6.
- **4 bits** long.
- Identifies the version of IP used.
- IPv4 = 4 (0100), IPv6 = 6 (0110)
### Traffic Class
The traffic class field is used to **classify** and **prioritize** packets.
- **6+2 bits** long.
	- The six most-significant bits hold the **differentiated services (DS)** field, which is used to classify packets.
	- The remaining two bits are used for **explicit congestion notification (ECN)**.
- It is used for **quality of service (QoS)** to indicate high-priority traffic.
### Flow Label
The flow label is used to identify packets belonging to the same **flow**\*.
- **20 bits** long.

>\*: A flow can be thought of as a sequence of packets that should receive similar treatment.
### Payload Length
The payload length field indicated the length of the payload, everything after the IPv6 header, in **bytes**.
- **16 bits** long.
### Next Header
The next header field indicates the type of the next header, which is the header of the encapsulated segment, such as TCP or UDP.
- **8 bits** long.
- It serves the same function as the **protocol** field in the IPv4 header.
### Hop Limit
The hop limit field specifies the maximum number of routers the packet can pass through.
- **8 bits** long.
- Each time the packet arrives at a router, the router decrements the hop limit by one.
- A router will drop a packet with a hop limit of 0.
- It serves the same function as the **TTL** field in the IPv4 header.
### Source Address
This **128 bits** long field contains the IPv6 address of the sender of the packet.
- The unicast IPv6 address of the sending node.
### Destination Address
This **128 bits** long field contains the IPv6 address of the intended receiver of the packet.
- The IPv6 unicast or multicast address of the destination node(s).
## Solicited-Node Multicast Address
A solicited-node multicast address is a multicast address used by the Neighbor Discovery Protocol (NDP) to **determine the link layer address associated with a given IPv6 address**.
- It is calculated from a unicast or anycast address.
	- *FF02:0000:0000:0000:0000:0001:FF* + the last 6 hexadecimal digits of the unicast or anycast address.
```text
2001:db8::2aa:ff:fe28:9c5a                        -- IPv6 Address (Compressed)
2001:0db8:0000:0000:02aa:00ff:fe28:9c5a           -- IPv6 Address (Uncompressed)
                                -- ----

ff02::1:ff00:0/104                                -- SNMA Prefix (Compressed)
ff02:0000:0000:0000:0000:0001:ff00:0000/104       -- SNMA Prefix (Uncompressed)
---- ---- ---- ---- ---- ---- --

ff02::1:ff28:9c5a                                 -- SNMA (Compressed)
ff02:0000:0000:0000:0000:0001:ff28:9c5a           -- SNMA (Uncompressed)
```
## Solicited-Node Multicast MAC Address
A solicited-node multicast MAC address is a multicast address used by the Neighbor Discovery Protocol (NDP) as a **destination MAC address when communicating to hosts using a solicited-node multicast address**.
- It is calculated from a solicited-node multicast address.
	- *33:33:FF* + the last 6 hexadecimal digits of the solicited-node multicast address.
```text
ff02::1:ff28:9c5a                                -- SNMA (Compressed)
          -- ----

33:33:FF:XX:XX:XX                                -- SNM MAC Address Prefix
33:33:FF:28:9C:5A                                -- SNM MAC Address
         -- -- --
```
## NDP (Neighbor Discovery Protocol)
NDP is an IPv6 protocol used by devices on the same local network to discover and communicate with their neighbors.
- It performs functions that ARP performs in IPv4, but NDP provides several additional capabilities.
- NDP uses ICMPv6 and solicited-node multicast addresses to learn the MAC addresses of other hosts.
### Router Solicitation & Router Advertisement
RS and RA are used for discovering routers and obtaining IPv6 network configuration.
- An RS message is sent by a host to request an immediate RA from routers on the local network. It is an ICMPv6 Type 133 message.
	- Sent to the multicast address *FF02::2*.
	- Asks all routers on the local link to identify themselves.
	- Sent when an interface is enabled or when a host connects to the network.
- An RA message is sent by a router to provide information about the IPv6 network. It is an ICMPv6 Type 134 message.
	- Sent to the multicast address *FF02::1*.
	- The router announces its precense, as well as other information about the link.
	- They are also sent periodically, even if the router has not received an RS.
### Neighbor Solicitation & Neighbor Advertisement
NS and NA are used for communication between a host and its neighbors. They are part of NDP and use ICMPv6.
- An NS message is sent when a device needs information about another IPv6 device. It is an ICMPv6 Type 135 message.
- An NA message is sent by a device to provide information about an IPv6 neighbor. It is an ICMPv6 Type 136 message.

## SLAAC (Stateless Address Autoconfiguration)
SLAAC is an IPv6 mechanism that allows a host to **automatically configure its own IPv6 address** without requiring a DHCPv6 server to assign the address.
- Hosts use the RS and RA messages to learn the IPv6 prefix of the local link and then automatically generate an IPv6 address.
	- Using `ipv6 address prefix/prefix-length eui-64` command, the prefix needs to be entered manually.
	- Using `ipv6 address autoconfig` command, the prefix does not need to be entered manually. The device **uses NDP to learn the prefix** used on the local link.
## DAD (Duplicate Address Detection)
DAD is an IPv6 mechanism **used to check whether an IPv6 address is already being used by another device** on the local link.
- Any time an IPv6-enabled interface initializes or an IPv6 address is configured on an interface, it performs DAD.
- DAD uses NS and NA.
- The host sends an NS for its own IPv6 address. If it does not receive a reply, it knows that the address is unique.
- If it receives a reply, it means that another host on the network is already using that address.
## IPv6 Static Routing
IPv6 static routing is the process of manually configuring a router with a route to an IPv6 network.
- IPv6 routing works the same way as IPv4 routing. However, the two processes are separate on the router and the two routing tables are separate as well.
- IPv6 routing is **disabled by default**. It must be enabled with the `ipv6 unicast-routing` command.
- If IPv6 routing is disabled, the router will be able to send and receive IPv6 traffic but will not route IPv6 traffic.
- A **connected network route** is automatically added for each connected network.
- A **local host route** is automatically added for each address configured on the router.
- Routes for **link-local addresses are not added to the routing table**.
- In IPv6, **directly attached** static routes **cannot be used if the interface is an Ethernet interface**.
