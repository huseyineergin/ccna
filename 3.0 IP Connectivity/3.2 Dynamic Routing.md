# 3.2 Dynamic Routing
## Introduction
**Dynamic routing** is a method where **routers automatically learn and update routes** to destination networks using routing protocols.
- Routers can use dynamic routing protocols to **advertise information about the routes they know** to other routers.
- If multiple routes to a destination are learned, the router determines which route is superior and adds it to the routing table.

**Floating static route** is a static route with a higher administrative distance than the primary route.
- Becomes active when the primary route is no longer available.
- The static route's AD must be higher than the primary route's AD.
- Commonly **used for route redundancy/failover**.

Dynamic routing protocols are categorized based on where they operate.
- IGP (Interior Gateway Protocol)
	- Used to exchange routing information **within a single autonomous system**.
	- Examples:
		- **RIP (Routing Information Protocol)**
		- **EIGRP (Enhanced Interior Gateway Routing Protocol)**
		- **OSPF (Open Shortest Path First)**
		- **IS-IS (Intermediate System to Intermediate System)**
- EGP (Exterior Gateway Protocol)
	- Used to exchange routing information **between different autonomous systems**.
	- Examples:
		- **BGP (Border Gateway Protocol)**

## Dynamic Routing Protocols
Dynamic routing protocols automatically learn and exchange routes between routers.
- `show ip protocols` command displays information about the configured IPv4 routing protocols.
- `passive-interface <int-id>` command prevents routing protocol messages from being sent through the specified interface.
- `passive-interface default` command configures all interfaces as passive by default.
- `no auto-summary` command disables automatic route summarization.
- `default-information originate` command advertises a default route to neighboring routers.
### Distance-Vector Routing Protocols
Routers **learn routes from their neighboring routers**. They typically **determine the best route based on a metric** such as hop count, bandwidth or delay.
- They were developed before link-state protocols.
- They operate by sending the following information to their directly connected neighbor:
	- Their **known destination networks**.
	- Their **metric to reach** their known destination networks.
- They are called distance-vector protocols because a router learns the **distance (metric)** and **vector (direction or next-hop)** for each route.
- Routers **do not have a complete view of the network topology**. They only know the routing information **provided by their neighbors**.
#### RIP (Routing Information Protocol)
A simple **distance-vector** routing protocol.
- Uses **hop count** as its metric. It ignores bandwidth.
- Maximum usable hop count is **15**. Anything more than that is considered unreachable.
- It has three versions:
	- **RIPv1** and **RIPv2**, used for IPv4.
	- **RIPng (RIP Next Generation)**, used for IPv6.
- It uses two message types:
	- **Request**: Used to ask neighboring RIP-enabled routers to send their routing tables.
	- **Response**: Used to send the local router's routing table to neighboring routers.
- By default, RIP-enabled routers share their routing tables every 30 seconds.
- Rarely used in modern networks because of its limitations.
- `router rip` command enables RIP and enters RIP router configuration mode.
- `network <network>` command enables RIP on interfaces belonging to the specified network and advertises those interfaces' networks through RIP.

**RIPv1**:
- Only advertises classful addresses. Therefore, doesn't support VLSM and CIDR.
- Doesnt't include subnet mask information in advertisements.
- Its messages are **broadcast** to *255.255.255.255*.

**RIPv2**:
- Supports VLSM and CIDR.
- Includes subnet mask information in advertisements.
- Its messages are **multicast** to *224.0.0.9*.
- `version 2` command configures the router to use RIPv2.
#### EIGRP (Enhanced Interior Gateway Routing Protocol)
An advanced **distance-vector** protocol developed by Cisco.
- Uses **bandwidth** and **delay** as its metric by default.
- Supports VLSM and CIDR.
- Doesn't have the 15 hop count limit of RIP.
- Reacts to network changes much faster than RIP.
- Its messages are **multicast** to *224.0.0.10*.
- Uses **wildcard mask**\* instead of subnet mask.
- It is the only IGP that **can perfom unequal-cost load balancing**.
- `router eigrp <as-num>` command enables EIGRP and enters EIGRP router configuration mode.
- `network <network> <wc-mask>` command enables EIGRP on interfaces whose IP addresses match the specified network and wildcard mask.
- `eigrp router-id <router-id>` command configures the EIGRP router ID.

>\*: A wildcard mask is basically an inverted subnet mask.
##### EIGRP Route Terminology
![EIGRP Network Topology](../Attachments/Images/EIGRP%20Network%20Topology.png)
```text
R1#show ip eigrp topology
...
P 192.168.4.0/24, 1 successors, FD is 28672
	via 10.0.12.2 (28672/28416), GigabitEthernet0/0
	via 10.0.13.2 (30976/28416), FastEthernet1/0
```
>The number on the left is R1’s metric, FD. The number on the right is R1’s neighbor’s metric, RD.

**Feasible Distance (FD)**:
- The **total metric from the local router to the destination** through a specific neighbor.
- The **lowest FD** identifies the best route.

**Reported Distance (RD)**:
- Also called **advertised distance (AD)**.
- The **metric that a neighboring router reports** to reach the destination.
- Does not include the metric from the local router to the neighbor.

**Successor**:
- The **best route** to a destination
- Has the **lowest feasible distance**.
- The successor route is installed in the routing table.

**Feasible Successor**:
- An **alternate route** to a destination.
- Must satisfy the **feasibility condition**\*:
    - **Reported Distance < Feasible Distance**
- Stored in the EIGRP topology table and can become the successor if the current successor fails.

>\*: The feasibility condition is used to select the successors and feasible successors that are guaranteed to be on a loop-free route to a destination.
### Link-State Routing Protocols
Routers learn about the network topology by **exchanging information about their links**. Each router **builds a map of the network** and **independently calculates the best path**.
- Each router **advertises information about its interfaces** to its neighbors. These advertisements are **forwarded throughout the network** until all routers in the network develop the same map of the network.
- Each router independently uses this map to **calculate the best routes** to each destination.
- They are tend to be **faster in reacting to changes** in the network than distance-vector protocols.
- They use **more resources** on the router because more information is shared.
#### IS-IS (Intermediate System to Intermediate System)
A **link-state** routing protocol.
- Uses **cost** as its metric.
- Uses the **SPF (Dijkstra) algorithm**.
- A single AS can be divided into smaller groups called **areas**.
- Supports hierarchical routing using **level 1** and **level 2**.
- Commonly used by large service-provider networks.
## Dynamic Routing Protocol Metrics
A metric is a value used by a routing protocol to **determine which route is the best path to a destination**.
- Different routing protocols use different metrics.
- The routing protocol uses its metric to select the best route and install it in the routing table.
- **Lower metric equals to better route** for most routing protocols.
- Metrics are used to compare routes **learned via the same routing protocol**.
- Common metrics include:
	- **Hop Count**: Number of routers a packet must pass through.
	- **Bandwidth**: Data-carrying capacity of a link.
	- **Delay**: Time required for a packet to reach the destination.
	- **Cost**: A value assigned to a route, often based on bandwidth.
	- **Load**: How busy a link is.
	- **Reliability**: How reliable a link is.
### ECMP (Equal-Cost Multi-Path)
ECMP is a routing feature that allows a router to use **multiple paths to the same destination when they have an equal metric**.
- Multiple routes have the same metric.
- The router can install multiple routes in its routing table.
- **Traffic will be load-balanced** across the available paths.
- Supported by protocols such as OSPF, EIGRP and IS-IS.
- `maximum-paths <num>` command configures the maximum number of equal-cost paths that can be installed in the routing table.
### AD (Administrative Distance)
A value used by a router to **determine which routing source is more trustworthy** when it learns the same destination from **different routing protocols**.
- Different routing protocols use different metrics, so they cannot be compared.
- The administrative distance is **used to determine which routing protocol is preferred**.
- A lower AD is preferred. It indicates that the routing protocol is considered more trustworthy.
- AD ranges from **0 to 255**.
	- 0 → Directly Connected
	- 1 → Static Route
	- 20 → eBGP (External BGP)
	- 90 → EIGRP
	- 100 → IGRP
	- 110 → OSPF
	- 115 → IS-IS
	- 120 → RIP
	- 170 → External EIGRP
	- 200 → iBGP (Internal BGP)
	- 255 → Unusable Route
- `ip route <ip-address> <subnet-mask> <next-hop> <ad>` command configures an IPv4 recursive static route with the specified administrative distance.
- `distance <ad>` command configures the administrative distance used by the routing protocol.
## OSPF (Open Shortest Path First)
A **link-state** routing protocol.
- Uses **cost** as its metric.
- Calculates the shortest path using the **SPF (Dijkstra) algorithm**.
- Supports hierarchical design using **areas**.
- Uses **wildcard mask** instead of subnet mask.
- It has three versions:
	- **OSPFv1**: Old, not used anymore.
	- **OSPFv2**: Used for IPv4.
	- **OSPFv3**: Used for IPv6. I can also be used for IPv4, but OSPFv2 is preferred.
- Routers store information about the network in **LSAs (Link-State Advertisements)**, which are organized in structure called the **LSDB (Link-State Database)**.
- Routers will **flood** LSAs until all routers in the OSPF area develop the same map of the network.
- `router ospf <process-id>` command enables OSPF and enters OSPF router configuration mode.
- `network <network> <wc-mask> area <area-id>` command enables OSPF on interfaces whose IP addresses match the specified network and wildcard mask and assigns them to the specified OSPF area.
- `router-id <router-id>` command configures the OSPF router ID.
- `clear ip ospf process` command restarts the OSPF process.
- `ip ospf <process-id> area <area-id>` command enables OSPF on the interface and assigns it to the specified OSPF area.
- `ip ospf priority <priority>` command configures the OSPF interface priority used in DR/BDR elections.
### OSPF Areas
An OSPF area is a **logical grouping of routers, networks and links** used to divide a large OSPF network into smaller sections.
- Helps **reduce the size of the LSDB** each router must maintain.
- Reduces the amount of **LSA flooding**.
- Reduces the processing required by the **SPF algorithm**.
- Routers in the same area share the same LSDB.
- **Area 0** is the **backbone area**. Other areas are connected to area 0.
- Routers can belong to different areas through interfaces. A router can have interfaces in multiple areas.
	- Routers connected to the backbone area are called **backbone routers**.
	- Routers with all interfaces in the same area are called **internal routers**.
	- Routers connecting different areas are called **area border routers (ABRs)**.
		- ABRs maintain seperate LSDB for each area they are connected to.
	- Routers that connect the OSPF network to an external network are called **autonomous system boundary routers (ASBRs)**.
- An **intra-area route** is a route to a destionation inside the same OSPF area.
- An **inter-area route** is a route to a destionation in a different OSPF area.

**OSPF Area Rules**:
- Areas should be contiguous.
- All areas must have at least one ABR connected to the backbone area.
- Interfaces in the same subnet must be in the same area.
### OSPF Metric
OSPF uses **cost** as its metric. It prefers the path with the **lowest total cost**.
- It is calculated by dividing **reference bandwidth** value by interface's bandwidth.
	- The default reference bandwidth is **100 Mbps**.
	- All **values less than 1 are converted to 1**.
		- Therefore, Fast Ethernet, Gigabit Ethernet, 10 Gigabit Ethernet, etc., are considered equal and all have a cost of 1 by default.
		- Loopback interfaces have a cost of 1.

There are three ways to modify the OSPF cost:
1. `auto-cost reference-bandwidth <mbps>` command sets the reference bandwidth.
2. `ip ospf cost <cost>` command manually sets the OSPF cost of an interface.
3. `bandwidth <kbps>` command changes the interface's bandwidth, which OSPF uses to calculate the cost. However, changing the bandwidth is not recommended.
### OSPF Neighbors
OSPF neighbors are routers that discover each other and establish an OSPF relationship to exchange routing information.
- When OSPF is activated on an interface, the router starts sending OSPF **hello messages** out of the interface at regular interval, which is determined by **hello timer**.
	- The default hello timer is 10 seconds on an Ethernet connection.
- OSPF hello messages are **multicast** to:
	- *224.0.0.5* for all OSPFv2 and OSPFv2 routers.
	- *FF02::5* for all OSPFv3 routers.
- `show ip ospf neighbor` command displays information about OSPF neighbors.
#### OSPF Neighbor Requirements
- Both routers must be on the **same subnet**.
- Both routers must be in the **same OSPF area**.
- OSPF process must be **up**.
- Each router must have a **unique router ID**.
- The **hello and dead timers** must match.
- The **authentication settings** must match, if authentication is configured.
- The **OSPF network type** must match*.
- **IP MTU settings** must match*.

>\*: Routers can become neighbors, but OSPF doesn't operate properly.
#### OSPF Neighbor States
OSPF neighbor states describe the **process of discovering a neighbor and establishing an OSPF connection**.
##### Down State
The initial OSPF neighbor state. No hello packet has been received from this neighbor yet.
- R1 sends a hello message to *224.0.0.5*.
- R1 doesn't know about R2 yet, so neighbor ID is empty.
- R1 doesn't know about its neighbor yet, so the current neighbor state is **down**.

![OSPF Neighbor States - Down](../Attachments/Images/OSPF%20Neighbor%20States%20-%20Down.png)
##### Init State
This state specifies that the router has received a hello packet from its neighbor, but the receiving router ID (RID) was not included in the hello packet.
- In R2's neighbor table, the relationship with R1 is now in the **init** state.
- R1 still doesn't know about R2, so R1 has no entries in its neighbor table.

![OSPF Neighbor States - Init](../Attachments/Images/OSPF%20Neighbor%20States%20-%20Init.png)
##### Two-Way State
This state designates that bi-directional communication has been established between two routers.
- R2 sends a hello packet containing the RIDs of both routers. R1 adds R2 to its neighbor table in the **two-way** state.
- R1 sends another hello packet, this time containing R2's RID. R2 changes R1's state to **two-way** state in its neighbor table.
- This state means that the router has received a **hello packet containing its own RID**.
- If both routers reach **two-way** state, it means that all the conditions have been met for them to become OSPF neighbors. They are now ready to exchange LSAs.
- In some network types, a **designated router (DR)** and a **backup designated router (BDR)** are elected at the end of this stage.

![OSPF Neighbor States - Two-Way](../Attachments/Images/OSPF%20Neighbor%20States%20-%20Two-Way.png)
##### Exstart State
This state begins the process of establishing an OSPF adjacency and determines which router will be the **master** for exchanging database description packets.
- Routers negotiate which one will be the **master** and which one will be the **slave**.
- To decide the master and slave, routers exchange **database description (DBD)** packets.
- The router with the **higher RID** becomes the master. It initiates the DBD exchange in the next state.
- Once the master/slave relationship is established, the routers move to the **exchange** state.
##### Exchange State
In this state, the routers exchange database bescription (DBD) packets to describe the contents of their LSDBs.
- DBD packets **do not contain the complete LSAs**; they only describe them.
- Routers compare the DBD information they receive with their own LSDBs to determine which LSAs they need to receive from their neighbors.
- Once the DBD exchange is complete, the routers move to the **loading** state.
##### Loading State
In this state, the routers request and receive any **missing or outdated LSAs** needed to synchronize their LSDBs.
- Routers send **link-state request (LSR)** packets to request missing LSAs.
- Routers respond with **link-state update (LSU)** packets, which contain the requested LSAs.
- Routers send **link-state acknowledgment (LSAck)** packets to confirm receipt of the LSAs.
- Once all required LSAs have been received and the LSDBs are synchronized, the routers move to the **F-full** state.

![OSPF Neighbor States - Loading](../Attachments/Images/OSPF%20Neighbor%20States%20-%20Loading.png)
##### Full State
The final OSPF neighbor state, indicating that the routers have **fully synchronized their LSDBs**.
- Routers have a full OSPF adjacency and **identical LSDBs**.
- Routers can now use the information in the LSDB to run the **SPF algorithm** and calculate the best routes.
- Routers continue exchanging hello packets to maintain the adjacency.
	- Every time a hello packet is received, the **dead timer**, which is 40 seconds by default, is reset.
	- If the dead timer counts down to 0 and no hello packet is received, the neighbor is removed.
- If the adjacency remains, the routers will continue exchanging LSAs as the network changes to ensure that each router has a complete and accurate map of the network.
### OSPF Message Types
| Type |               Name                |                               Purpose                                |
| :--: | :-------------------------------: | :------------------------------------------------------------------: |
|  1   |               Hello               |                 Neighbor discovery and maintenance.                  |
|  2   |    Database Description (DBD)     |                  Summary of the LSDB of the router.                  |
|  3   |     Link-State Request (LSR)      |              Requests specific LSAs from the neighbor.               |
|  4   |      Link-State Update (LSU)      |                 Sends specific LSAs to the neighbor.                 |
|  5   | Link-State Acknowedgement (LSAck) | Used to acknowledge that the router received LSAs from its neighbor. |
### OSPF LSA Types
LSAs are pieces of information that OSPF routers use to describe the network topology and routes.
- `show ip ospf database` command displays the OSPF link-state database.
#### Type 1 - Router LSA
Describes the links and interfaces of an OSPF router within an area.
- Generated by **every OSPF router**.
- It identifies the router using its RID.
- Contains the router's **links and connected networks**.
- Used to build the OSPF topology.
#### Type 2 - Network LSA
Describes a multi-access (i.e., broadcast) network and the routers connected to it.
- Generated by the **DR**.
- Lists **routers connected to that network segment**.
- Used to build the OSPF topology.
#### Type 5 - AS External LSA
Describes routes learned from outside the OSPF autonomous system.
- Generated by an **ASBR**.
- Advertises external routes into OSPF.
### OSPF Network Types
OSPF network types define **how OSPF routers communicate with each other** and whether a **DR/BDR election** is required.
- `ip ospf network <network-type>` command configures the OSPF network type for an interface.
	- `broadcast`: Broadcast network type. Supports DR/BDR election.
	- `non-broadcast`: Non-broadcast multiaccess (NBMA). Supports DR/BDR election but requires neighbors to be configured manually.
	- `point-to-point`: Point-to-point network. No DR/BDR election.
#### Broadcast
Allows multiple routers to communicate over the same broadcast network.
- Enabled by default on **Ethernet** and **FDDI (Fiber Distributed Data Interface)** interfaces.
- Routers dynamically discover neighbors by sending and listening OSPF hello packets using multicast address *224.0.0.5*.
- A **designated router (DR)** and a **backup designated router (BDR)** must be elected on each subnet.
- Routers that aren't the DR or BDR become **DROther**.
##### DR/BDR
On OSPF broadcast networks, routers elect a DR and BDR to **reduce the number of OSPF adjacencies**.
- Without a DR/BDR, every router would need to form an adjacency with every other router.
- The DR acts as the central point for exchanging LSAs on the network.
- The BDR is the backup for the DR.
- DROther routers **form full adjacencies with the DR and BDR**.
- DROther routers **do not form full adjacencies with each other**. They remain in the **two-way** state.
- Therefore, routers only exchange LSAs with the DR and BDR.
- Messages to the DR and BDR are multicast to *224.0.0.6*.

**DR/BDR Election**:
1. The router with the **highest OSPF interface priority** becomes the DR.
2. The router with the **second-highest priority** becomes the BDR.
3. If priorities are equal, the router with the **highest RID** becomes DR.
- Default OSPF interface priority is **1** on all interfaces.
- A priority of **0** makes the router **ineligible** to become DR or BDR.
- The election is **not preemptive**.
	- If a new router with a higher priority joins later, it does not replace the existing DR.
	- A new election occurs when the current DR fails or OSPF is reset.
- When DR goes down, BDR becomes the new DR. Then an election is held for the new BDR.
#### Point-to-Point
Connects two routers directly.
- Enabled by default on serial interfaces using **PPP (Point-to-Point Protocol)** and **HDLC (High-Level Data Link Control)** encapsulations.
- Routers dynamically discover neighbors by sending and listening OSPF hello packets using multicast address *224.0.0.5*.
- No DR/BDR election.
- Routers form a full adjacency.
