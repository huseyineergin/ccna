# 3.2 Dynamic Routing
## Introduction
**Dynamic routing** is a method where **routers automatically learn and update routes** to destination networks using routing protocols.
- Routers can use dynamic routing protocols to **advertise information about the routes they know** to other routers.
- If multiple routes to a destination are learned, the router determines which route is superior and adds it to the routing table.

**Floating static route** is a static route with a higher administrative distance than the primary route.
- Becomes active when the primary route is no longer available.
- The static route's AD must be higher than the primary route's AD.
- Commonly **used for route redundancy/failover**.

Dynamic routing protocols are categorized based on where they operate.
- IGP (Interior Gateway Protocol)
	- Used to exchange routing information **within a single autonomous system**.
	- Examples:
		- **RIP (Routing Information Protocol)**
		- **EIGRP (Enhanced Interior Gateway Routing Protocol)**
		- **OSPF (Open Shortest Path First)**
		- **IS-IS (Intermediate System to Intermediate System)**
- EGP (Exterior Gateway Protocol)
	- Used to exchange routing information **between different autonomous systems**.
	- Examples:
		- **BGP (Border Gateway Protocol)**

## Dynamic Routing Protocols
Dynamic routing protocols automatically learn and exchange routes between routers.
### Distance-Vector Routing Protocols
Routers **learn routes from their neighboring routers**. They typically **determine the best route based on a metric** such as hop count, bandwidth or delay.
- They were developed before link-state protocols.
- They operate by sending the following information to their directly connected neighbor:
	- Their **known destination networks**.
	- Their **metric to reach** their known destination networks.
- They are called distance-vector protocols because a router learns the **distance (metric)** and **vector (direction or next-hop)** for each route.
- Routers **do not have a complete view of the network topology**. They only know the routing information **provided by their neighbors**.
#### RIP (Routing Information Protocol)
A simple **distance-vector** routing protocol.
- Uses **hop count** as its metric. It ignores bandwidth.
- Maximum usable hop count is **15**. Anything more than that is considered unreachable.
- It has three versions:
	- **RIPv1** and **RIPv2**, used for IPv4.
	- **RIPng (RIP Next Generation)**, used for IPv6.
- It uses two message types:
	- **Request**: Used to ask neighboring RIP-enabled routers to send their routing tables.
	- **Response**: Used to send the local router's routing table to neighboring routers.
- By default, RIP-enabled routers share their routing tables every 30 seconds.
- Rarely used in modern networks because of its limitations.

**RIPv1**:
- Only advertises classful addresses. Therefore, doesn't support VLSM and CIDR.
- Doesnt't include subnet mask information in advertisements.
- Its messages are **broadcast** to *255.255.255.255*.

**RIPv2**:
- Supports VLSM and CIDR.
- Includes subnet mask information in advertisements.
- Its messages are **multicast** to *224.0.0.9*.
#### EIGRP (Enhanced Interior Gateway Routing Protocol)
An advanced **distance-vector** protocol developed by Cisco.
- Uses **bandwidth** and **delay** as its metric by default.
- Supports VLSM and CIDR.
- Doesn't have the 15 hop count limit of RIP.
- Reacts to network changes much faster than RIP.
- Its messages are **multicast** to *224.0.0.10*.
- Uses **wildcard mask**\* instead of subnet mask.
- It is the only IGP that **can perfom unequal-cost load balancing**.

>\*: A wildcard mask is basically an inverted subnet mask.
##### EIGRP Route Terminology

>The number on the left is R1’s metric, FD. The number on the right is R1’s neighbor’s metric, RD.

**Feasible Distance (FD)**:
- The **total metric from the local router to the destination** through a specific neighbor.
- The **lowest FD** identifies the best route.

**Reported Distance (RD)**:
- Also called **advertised distance (AD)**.
- The **metric that a neighboring router reports** to reach the destination.
- Does not include the metric from the local router to the neighbor.

**Successor**:
- The **best route** to a destination
- Has the **lowest feasible distance**.
- The successor route is installed in the routing table.

**Feasible Successor**:
- An **alternate route** to a destination.
- Must satisfy the **feasibility condition**\*:
    - **Reported Distance < Feasible Distance**
- Stored in the EIGRP topology table and can become the successor if the current successor fails.

>\*: The feasibility condition is used to select the successors and feasible successors that are guaranteed to be on a loop-free route to a destination.
### Link-State Routing Protocols
Routers learn about the network topology by **exchanging information about their links**. Each router **builds a map of the network** and **independently calculates the best path**.
- Each router **advertises information about its interfaces** to its neighbors. These advertisements are **forwarded throughout the network** until all routers in the network develop the same map of the network.
- Each router independently uses this map to **calculate the best routes** to each destination.
- They are tend to be **faster in reacting to changes** in the network than distance-vector protocols.
- They use **more resources** on the router because more information is shared.
#### OSPF (Open Shortest Path First)
A **link-state** routing protocol.
- Uses **cost** as its metric.
- Calculates the shortest path using the **SPF (Dijkstra) algorithm**.
- Supports hierarchical design using **areas**.
- Uses **wildcard mask** instead of subnet mask.
- It has three versions:
	- **OSPFv1**: Old, not used anymore.
	- **OSPFv2**: Used for IPv4.
	- **OSPFv3**: Used for IPv6. I can also be used for IPv4, but OSPFv2 is preferred.
- Routers store information about the network in **LSAs (Link-State Advertisements)**, which are organized in structure called the **LSDB (Link-State Database)**.
- Routers will **flood** LSAs until all routers in the OSPF area develop the same map of the network.
##### OSPF Areas
An OSPF area is a **logical grouping of routers, networks and links** used to divide a large OSPF network into smaller sections.
- Helps **reduce the size of the LSDB** each router must maintain.
- Reduces the amount of **LSA flooding**.
- Reduces the processing required by the **SPF algorithm**.
- Routers in the same area share the same LSDB.
- **Area 0** is the **backbone area**. Other areas are connected to area 0.
- Routers can belong to different areas through interfaces. A router can have interfaces in multiple areas.
	- Routers connected to the backbone area are called **backbone routers**.
	- Routers with all interfaces in the same area are called **internal routers**.
	- Routers connecting different areas are called **area border routers (ABRs)**.
		- ABRs maintain seperate LSDB for each area they are connected to.
	- Routers that connect the OSPF network to an external network are called **autonomous system boundary routers (ASBR)**.
- An **intra-area route** is a route to a destionation inside the same OSPF area.
- An **inter-area route** is a route to a destionation in a different OSPF area.

**OSPF Area Rules**:
- Areas should be contiguous.
- All areas must have at least one ABR connected to the backbone area.
- Interfaces in the same subnet must be in the same area.
#### IS-IS (Intermediate System to Intermediate System)
A **link-state** routing protocol.
- Uses **cost** as its metric.
- Uses the **SPF (Dijkstra) algorithm**.
- A single AS can be divided into smaller groups called **areas**.
- Supports hierarchical routing using **level 1** and **level 2**.
- Commonly used by large service-provider networks.
## Dynamic Routing Protocol Metrics
A metric is a value used by a routing protocol to **determine which route is the best path to a destination**.
- Different routing protocols use different metrics.
- The routing protocol uses its metric to select the best route and install it in the routing table.
- **Lower metric equals to better route** for most routing protocols.
- Metrics are used to compare routes **learned via the same routing protocol**.
- Common metrics include:
	- **Hop Count**: Number of routers a packet must pass through.
	- **Bandwidth**: Data-carrying capacity of a link.
	- **Delay**: Time required for a packet to reach the destination.
	- **Cost**: A value assigned to a route, often based on bandwidth.
	- **Load**: How busy a link is.
	- **Reliability**: How reliable a link is.
### ECMP (Equal-Cost Multi-Path)
ECMP is a routing feature that allows a router to use **multiple paths to the same destination when they have an equal metric**.
- Multiple routes have the same metric.
- The router can install multiple routes in its routing table.
- **Traffic will be load-balanced** across the available paths.
- Supported by protocols such as OSPF, EIGRP and IS-IS.
### AD (Administrative Distance)
A value used by a router to **determine which routing source is more trustworthy** when it learns the same destination from **different routing protocols**.
- Different routing protocols use different metrics, so they cannot be compared.
- The administrative distance is **used to determine which routing protocol is preferred**.
- A lower AD is preferred. It indicates that the routing protocol is considered more trustworthy.
- AD ranges from **0 to 255**.
	- 0 → Directly Connected
	- 1 → Static Route
	- 20 → eBGP (External BGP)
	- 90 → EIGRP
	- 100 → IGRP
	- 110 → OSPF
	- 115 → IS-IS
	- 120 → RIP
	- 170 → External EIGRP
	- 200 → iBGP (Internal BGP)
	- 255 → Unusable Route
