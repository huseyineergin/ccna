# 5.1 ACLs
## Introduction
**ACLs (Access Control Lists)** are sets of rules used by a network device to permit or deny network traffic.
- They function as packet filters, instructing the device to permit or discard traffic.
- They can filter traffic based on IP addresses, ports, protocols, etc.
- They are an **ordered** sequence of ACEs.
- Configuring an ACL in global configuration mode does not make it take effect. The ACL must be applied to an interface.
- They are applied either **inbound** or **outbound**.
- If a packet matches one of the ACEs in the ACL, the device takes the specified action and stops processing the ACL. All entries below the matching entry are ignored.
- A **maximum of one ACL** can be applied to a single interface **in each direction**.
- Every ACL has an **implicit deny** at the end. If a packet does not match any explicit ACE, it is denied.

An **ACE (Access Control Entry)** is one individual rule inside an ACL.
## Standard ACLs
Standard ACLs filter traffic based **only on the source IPv4 address**.
- Standard ACLs should be applied as close to the destination as possible.
### Standard Numbered ACLs
A standard numbered ACL is identified by a **number**.
- Different types of ACLs have different ranges of numbers that can be used.
	- Standard ACLs can use the number ranges 1–99 and 1300–1999.
- `access-list <access-list-num> {deny | permit} <src-ip> <wc-mask>` command is used to configure a standard numbered ACL.
	- `access-list 10 deny 192.168.1.0 0.0.0.255`
	- `access-list 10 permit any`
- `ip access-group <access-list-num> {in | out}` command is used to apply a standard numbered ACL to an interface.
	- `ip access-group 10 out`
### Standard Named ACLs
A standard named ACL is identified by a **name** rather than a number.
- Standard named ACLs are configured by entering **standard ACL configuration mode** and then configuring each entry in that mode.
	- `ip access-list standard <access-list-name>` command is used to enter standard ACL configuration mode.
		- `ip access-list standard BLOCK_HR`
- `[sequence-num] {deny | permit} <source-ip> <wc-mask>` command is used to configure an ACE in a standard ACL.
	- `5 deny 192.168.1.0 0.0.0.255`
	- `permit any`
- `ip access-group <access-list-name> {in | out}` command is used to apply a standard named ACL to an interface.
	- `ip access-group BLOCK_HR in`
## Extended ACLs
Extended ACLs can filter traffic based on more parameters, making them more precise than standard ACLs.
- They can use source IP addresses, destination IP addresses, protocol and port numbers to filter traffic.
### Extended Numbered ACLs
An extended numbered ACL is identified by a **number**.
- Different types of ACLs have different ranges of numbers that can be used.
	- Extended ACLs can use the number ranges 100–199 and 2000–2699.
- `access-list <access-list-num> {deny | permit} <protocol> <src-ip> <src-wc-mask> <dest-ip> <dest-wc-mask>` command is used to configure an extended numbered ACL.
	- `access-list 100 deny tcp 192.168.1.0 0.0.0.255 10.0.1.0 0.0.0.255`
	- `access-list 100 deny udp any 10.0.1.0 0.0.0.255`
	- `access-list 100 permit ip any any`
- Extended numbered ACLs can be applied to interfaces in the same way as standard numbered ACLs.
### Extended Named ACLs
An extended named ACL is identified by a **name** rather than a number.
- Extended named ACLs are configured by entering **extended ACL configuration mode** and then configuring each entry in that mode.
	- `ip access-list extended {<access-list-name> | <access-list-num>}` command is used to enter extended ACL configuration mode.
		- `ip access-list extended BLOCK_HR`
- `[sequence-num] {deny | permit} <protocol> <src-ip> <src-wc-mask> <dest-ip> <dest-wilcard-mask>` command is used to configure an ACE in an extended ACL.
	- `5 deny tcp 192.168.1.0 0.0.0.255 10.0.1.0 0.0.0.255`
	- `deny udp any 10.0.1.0 0.0.0.255`
	- `permit ip any any`
- Extended named ACLs can be applied to interfaces in the same way as standard named ACLs.
### Matching TCP/UDP Port Numbers
When matching TCP/UDP traffic, source and/or destination port numbers can optionally be specified to match.
- `access-list <access-list-num> {deny | permit} {tcp | udp} <src-ip> <src-wc-mask> [src-port] <dest-ip> <dest-wc-mask> [dest-port]` command is used to configure an extended numbered ACL for TCP/UDP traffic based on IP addresses and port numbers.
	- `access-list 100 deny tcp 192.168.1.0 0.0.0.255 10.0.1.0 0.0.0.255 eq 80`
	- `access-list 100 deny udp any 10.0.1.0 0.0.0.255 neq 161`
	- `access-list 100 permit tcp any any range 20 21`
- `[sequence-num] {deny | permit} {tcp | udp} <src-ip> <src-wc-mask> [src-port] <dest-ip> <dest-wc-mask> [dest-port]` command is used to configure an extended ACL for TCP/UDP traffic based on IP addresses and port numbers.
	- `5 deny tcp 192.168.1.0 0.0.0.255 10.0.1.0 0.0.0.255 eq 80`
	- `deny udp any 10.0.1.0 0.0.0.255 neq 161`
	- `permit tcp any any range 20 21`
