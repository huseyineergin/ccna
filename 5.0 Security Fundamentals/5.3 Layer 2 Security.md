# 5.3 Layer 2 Security
## Port Security
Port Security is a Layer 2 security feature that controls which devices can connect to a switch port by limiting the MAC addresses allowed on that port.
- If an unauthorized source MAC address enters the port, an action will be taken.
	- By default, the port will be placed in an **err-disabled** state.
- When port security is enabled on an interface with the default settings, one MAC address is allowed.
	- The allowed MAC address can be configured manually.
	- If no MAC address is configured manually, the switch allows the first source MAC address detected on the interface.
- The maximum number of allowed MAC addresses can be changed.
	- `(config-if)#switchport port-security maximum <num>` command sets the maximum number of secure MAC addresses allowed on the interface.
- A combination of manually configured MAC addresses and dynamically learned addresses is possible.
	- Sticky and statically configured secure MAC addresses are listed as **STATIC** in the MAC address table.
	- Dynamically learned secure MAC addresses are listed as **DYNAMIC** in the MAC address table.
	- `#show mac address-table secure` command displays secure MAC address entries in the MAC address table.
- Port security allows network administrators to control which devices are permitted to access the network.
	- However, MAC address spoofing is relatively easy to perform.
	- A device can be configured to send frames using a different source MAC address.
	- Rather than manually specifying the permitted MAC addresses on each port, limiting the number of MAC addresses allowed on an interface is often more practical.
- Port security can be enabled on access ports or trunks ports, but they must be **statically configured as access or trunk**.
	- `(config-if)#switchport port-security` command enables port security on the interface with the default settings.
- `(config-if)#switchport port-security mac-address <mac-addr>` command statically configures the specified MAC address as a secure MAC address on the interface.
- `(config)#errdisable recovery cause psecure-violation` command enables automatic recovery of interfaces disabled due to port-security violations.
- `#show port-security interface <int-id>` command displays port security settings and status for the specified interface.
### Port Security Violation Modes
There are three violation modes that determine what the switch will do if an unauthorized frame enters an interface configured with port security.
- **Shutdown**
	- Effectively shuts down the port by placing it in an **err-disabled** state.
	- Generates a syslog and/or SNMP message when the interface is disabled.
	- Sets the violation counter to 1 when the interface is disabled.
	- This is the default violation mode.
- **Restrict**
	- The switch discards traffic from unauthorized MAC addresses.
	- The interface is **not** disabled.
	- Generates a syslog and/or SNMP message each time an unauthorized MAC address is detected.
	- Increments the violation counter by 1 for each unauthorized frame.
	- `(config-if)#switchport port-security violation restrict` command changes the port security violation mode to restrict.
- **Protect**
	- The switch discards traffic from unauthorized MAC addresses.
	- The interface is **not** disabled.
	- No syslog or SNMP messages are generated for unauthorized traffic.
	- The violation counter is **not** incremented.
	- `(config-if)#switchport port-security violation protect` command changes the port security violation mode to protect.
### Port Security Aging Time
Port security aging time allows secure MAC addresses learned through port security to be removed after a specified period.
- By default secure MAC addresses will **not** age out.
	- Aging time can be configured with `(config-if)#switchport port-security aging time <minutes>` command.
- There are multiple aging types.
	- **Absolute**: Once learned, a secure MAC address is removed when the aging timer expires, even if traffic is still being received from that address. After the MAC address ages out, it can be relearned immediately when another frame arrives from the same source MAC address.
	- **Inactivity**: After the secure MAC address is learned, the aging timer starts but is reset each time a frame from that source MAC address is received on the interface.
	- Aging type can be configured with `(config-if)#switchport port-security aging type <aging-type>` command.
	- By default, only dynamically learned secure MAC addresses will age out.
		- `switchport port-security aging static` command enables aging for statically configured secure MAC addresses on the interface.
### Port Security Sticky Secure MAC Addresses
Sticky secure MAC addresses are a port security feature that allows a switch to dynamically learn the MAC address of a connected device and automatically add it as a static secure entry to the running configuration.
- It can be enabled with `(config-if)#switchport port-security mac-address sticky` command.
	- When it is enabled, all currently dynamically learned secure MAC addresses are converted to sticky secure MAC addresses.
	- When it is disabled, all current sticky secure MAC addresses are converted to regular dynamically learned secure MAC addresses.
- When enabled, dynamically learned secure MAC addresses are added to the running configuration as follows:
	- `switchport port-security mac-address sticky <mac-addr>`
- The sticky secure MAC addresses will **never** age out.
	- The running configuration must be saved to the startup configuration to make them permanent.
