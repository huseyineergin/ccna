# 5.3 Layer 2 Security
## Port Security
Port security is a Layer 2 security feature that controls which devices can connect to a switch port by limiting the MAC addresses allowed on that port.
- If an unauthorized source MAC address enters the port, an action will be taken.
	- By default, the port will be placed in an **err-disabled** state.
- When port security is enabled on an interface with the default settings, one MAC address is allowed.
	- The allowed MAC address can be configured manually.
	- If no MAC address is configured manually, the switch allows the first source MAC address detected on the interface.
- The maximum number of allowed MAC addresses can be changed.
	- `(config-if)#switchport port-security maximum <num>` command sets the maximum number of secure MAC addresses allowed on the interface.
- A combination of manually configured MAC addresses and dynamically learned addresses is possible.
	- Sticky and statically configured secure MAC addresses are listed as **STATIC** in the MAC address table.
	- Dynamically learned secure MAC addresses are listed as **DYNAMIC** in the MAC address table.
	- `#show mac address-table secure` command displays secure MAC address entries in the MAC address table.
- Port security allows network administrators to control which devices are permitted to access the network.
	- However, MAC address spoofing is relatively easy to perform.
	- A device can be configured to send frames using a different source MAC address.
	- Rather than manually specifying the permitted MAC addresses on each port, limiting the number of MAC addresses allowed on an interface is often more practical.
- Port security can be enabled on access ports or trunks ports, but they must be **statically configured as access or trunk**.
	- `(config-if)#switchport port-security` command enables port security on the interface with the default settings.
- `(config-if)#switchport port-security mac-address <mac-addr>` command statically configures the specified MAC address as a secure MAC address on the interface.
- `(config)#errdisable recovery cause psecure-violation` command enables automatic recovery of interfaces disabled due to port-security violations.
- `#show port-security interface <int-id>` command displays port security settings and status for the specified interface.
### Port Security Violation Modes
There are three violation modes that determine what the switch will do if an unauthorized frame enters an interface configured with port security.
- **Shutdown**
	- Effectively shuts down the port by placing it in an **err-disabled** state.
	- Generates a Syslog and/or SNMP message when the interface is disabled.
	- Sets the violation counter to 1 when the interface is disabled.
	- This is the default violation mode.
- **Restrict**
	- The switch discards traffic from unauthorized MAC addresses.
	- The interface is **not** disabled.
	- Generates a Syslog and/or SNMP message each time an unauthorized MAC address is detected.
	- Increments the violation counter by 1 for each unauthorized frame.
	- `(config-if)#switchport port-security violation restrict` command changes the port security violation mode to restrict.
- **Protect**
	- The switch discards traffic from unauthorized MAC addresses.
	- The interface is **not** disabled.
	- No Syslog or SNMP messages are generated for unauthorized traffic.
	- The violation counter is **not** incremented.
	- `(config-if)#switchport port-security violation protect` command changes the port security violation mode to protect.
### Port Security Aging Time
Port security aging time allows secure MAC addresses learned through port security to be removed after a specified period.
- By default secure MAC addresses will **not** age out.
	- Aging time can be configured with `(config-if)#switchport port-security aging time <minutes>` command.
- There are two aging types.
	- **Absolute**: Once learned, a secure MAC address is removed when the aging timer expires, even if traffic is still being received from that address. After the MAC address ages out, it can be relearned immediately when another frame arrives from the same source MAC address.
	- **Inactivity**: After the secure MAC address is learned, the aging timer starts but is reset each time a frame from that source MAC address is received on the interface.
	- Aging type can be configured with `(config-if)#switchport port-security aging type <aging-type>` command.
	- By default, only dynamically learned secure MAC addresses will age out.
		- `switchport port-security aging static` command enables aging for statically configured secure MAC addresses on the interface.
### Port Security Sticky Secure MAC Addresses
Sticky secure MAC addresses are a port security feature that allows a switch to dynamically learn the MAC address of a connected device and automatically add it as a static secure entry to the running configuration.
- It can be enabled with `(config-if)#switchport port-security mac-address sticky` command.
	- When it is enabled, all currently dynamically learned secure MAC addresses are converted to sticky secure MAC addresses.
	- When it is disabled, all current sticky secure MAC addresses are converted to regular dynamically learned secure MAC addresses.
- When enabled, dynamically learned secure MAC addresses are added to the running configuration as follows:
	- `switchport port-security mac-address sticky <mac-addr>`
- The sticky secure MAC addresses will **never** age out.
	- The running configuration must be saved to the startup configuration to make them permanent.
## DHCP Snooping
DHCP snooping is a Layer 2 security feature on switches that protects a network against DHCP-based attacks.
- It is used to filter DHCP messages received on **untrusted** ports. All ports are untrusted by default.
	- `(config-if)#ip dhcp snooping trust` command configures the interface as trusted for DHCP snooping.
- Usually, **uplink** ports are configured as trusted ports and **downlink** ports remain untrusted.
- When filtering DHCP messages, DHCP snooping distinguishes between DHCP server and client messages.
	- DHCP server messages received on an untrusted port are always discarded without further checks.
		- **OFFER**: Used to offer an IP address to a DHCP client.
		- **ACK**: Used to confirm the DHCP client's IP address request and lease.
		- **NAK**: Used to reject a DHCP client's REQUEST.
	- DHCP client messages are inspected before the switch decides whether to forward or discard them.
		- **DISCOVER**: Used to find available DHCP servers on the network.
		- **REQUEST**: Used to request an offered IP address or renew its existing lease.
		- **RELEASE**: Used to inform the DHCP server that it no longer needs its assigned IP address.
		- **DECLINE**: Used to decline the IP address offered by a DHCP server.
- `(config)#ip dhcp snooping` command enables DHCP snooping globally on the switch.
- `(config)#ip dhcp snooping vlan <vlan-id>` command enables DHCP snooping on the specified VLAN.

### DHCP Snooping Operations
DHCP snooping operations describe how a switch processes DHCP messages, distinguishes trusted from untrusted ports, filters invalid messages, and builds a DHCP snooping binding table.
- DHCP messages received on a trusted port are forwarded normally without inspection.
- DHCP messages received on an untrusted port are inspected as follows:
	- DHCP server messages are discarded.
	- DHCP client messages undergo the following checks:
		- **DISCOVER/REQUEST Messages**: The frame's source MAC address is checked against the DHCP message's CHADDR field. If they match, the message is forwarded; otherwise, it is discarded.
		- **RELEASE/DECLINE Messages**: The packet's source IP address and the receiving interface must match the entry in the DHCP snooping binding table. If both match, the message is forwarded; otherwise, it is discarded.
			- When a client successfully leases an IP address from a DHCP server, a new entry is added to the DHCP snooping binding table.
- `#show ip dhcp snooping binding` command displays the DHCP snooping binding table, including client IP and MAC addresses, VLANs and interfaces.
### DHCP Snooping Rate Limiting
DHCP snooping rate limiting is a switch security feature that limits how many DHCP packets an interface can receive.
- If the DHCP message rate exceeds the configured limit, the interface is placed in an **err-disabled** state.
- The interface can be manually reenabled or automatically reenabled using errdisable recovery.
	- `(config)#errdisable recovery cause dhcp-rate-limit` command enables automatic recovery of interfaces disabled due to DHCP snooping rate limit violations.
- `(config-if)#ip dhcp snooping limit rate <num>` command sets the maximum number of DHCP messages the interface can receive per second.
- Rate limiting can be useful for protecting against DHCP exhaustion attacks.
### DHCP Option 82 (Information Option)
DHCP option 82 is a DHCP feature called the **relay agent information option**. It allows a network switch or DHCP relay agent to add information about where a DHCP request came from before forwarding it to a DHCP server.
- It provides additional information about the DHCP relay agent that received the client's message, including the receiving interface and VLAN.
- By default, switches with DHCP snooping enabled add option 82 to DHCP messages received from clients, **even when they are not acting as DHCP relay agents**.
- By default, switches discard DHCP messages containing option 82 when they are received on an untrusted port.
- `(config)#no ip dhcp snooping information option` command disables the insertion of DHCP option 82 information into DHCP messages.
## Dynamic ARP Inspection (DAI)
DAI is a Layer 2 security feature on switches that protects a network against ARP-based attacks.
- It is used to filter ARP messages received on **untrusted** ports. All ports are untrusted by default.
	- `(config-if)#ip arp inspection trust` command configures the interface as trusted for DAI.
- Usually, all **ports connected to other network devices** should be configured as trusted, while **interfaces connected to end hosts** should remain untrusted.
- `(config)#ip arp inspection vlan <vlan-id>` command enables DAI on the specified VLAN.
- `#show ip arp inspection interfaces` command displays the DAI trust state and ARP packet rate limit for all interfaces.
- `#show ip arp inspection` command displays the DAI status, validation settings and VLAN configuration.

![DAI - Ports](../Attachments/Images/DAI%20-%20Ports.png)
### Dynamic ARP Inspection Operations
DAI operations describe how a switch examines ARP packets, validates their contents and decides whether to forward or drop them.
- ARP messages received on a trusted port are forwarded normally without inspection.
- DAI inspects the **sender MAC** and **sender IP** fields of ARP messages received on **untrusted** ports and checks for a matching entry in the DHCP snooping binding table.
	- If a matching entry exists, the ARP message is forwarded normally.
	- If no matching entry exists, the ARP message is discarded.
- DAI can also be configured to perform more in-depth, optional checks.
	- `(config)#ip arp inspection validate <options>` command enables additional DAI checks on ARP packets.
		- `src-mac`: Checks the source MAC address in the Ethernet header against the sender’s MAC address in the ARP body.
		- `dst-mac`: Checks the destination MAC address in the Ethernet header against the target MAC address in the ARP body.
		- `ip`: Checks the ARP body for invalid and unexpected IP addresses.
- **ARP ACLs** can be manually configured to define IP-to-MAC address mappings for DAI to check. This is useful for hosts that do not use DHCP.
#### ARP ACLs
ARP ACLs on switches are rules that define which IP-to-MAC address mappings are permitted in ARP packets.
- `(config)#arp access-list <acl-name>` command creates an ARP ACL for filtering ARP packets during DAI.
- `(config-arp-nacl)#permit ip host <ip-addr> mac host <mac-addr>` command permits ARP packets from the specified IP and MAC address pair.
- `(config)#ip arp inspection filter <acl-name> vlan <vlan-id>` command applies the specified ARP ACL to the VLAN for DAI.
### Dynamic ARP Inspection Rate Limiting
DAI rate limiting is a switch security feature that limits how many ARP packets an interface can receive.
- If the ARP message rate exceeds the configured limit, the interface is placed in an **err-disabled** state.
- The interface can be manually reenabled or automatically reenabled using errdisable recovery.
	- `(config)#errdisable recovery cause arp-inspection` command enables automatic recovery of interfaces disabled due to DAI rate limit violations.
- DAI rate limiting is enabled by default on untrusted ports, with a limit of 15 packets per second. It is disabled by default on trusted ports.
	- DAI **burst interval** allows rate limiting to be configured as a **number of packets per number of seconds**.
	- `(config-if)#ip arp inspection limit rate <num> [burst interval <seconds>]` command limits incoming ARP packets and optionally specifies the consecutive interval for monitoring the rate.
