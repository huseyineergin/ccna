# 1.7 TCP & UDP
## Introduction
The Transport layer is layer 4 of the OSI model. Its main job is to provide **end-to-end communication** between applications running on different devices.
- Uses port numbers to identify applications.

A **session** is an exchange of data between two or more communicating devices.

The port numbers that protocols use are registered by **IANA (Internet Assigned Numbers Authority)**:
- **Well-Known**: 0-1023
- **Registered**: 1024-49151
- **Ephemeral**: 49152-65535
## TCP (Transmission Control Protocol)
TCP is a layer 4 transport protocol that provides **reliable** and **connection-oriented** communication between applications over a network.
- TCP **establishes a connection between sender and receiver** before sending data. Once the connection is established, the data exchange begins.
- The **destination host must acknowledge the receipt of each TCP segment**. If a segment is not acknowledged, it is retransmitted.
- TCP uses **checksums** to detect corrupted segments. Corrupted data can be sent again.
- TCP provides **sequencing**. Sequence numbers in the TCP header allow destination hosts to put segments in the correct order, even if they arrive out of order.
- TCP provides **flow control**. The destination host can tell the source host to increase or decrease the rate at which data is sent.
### TCP Three-Way Handshake
The TCP three-way handshake is the process used to **establish a TCP connection between a client and a before data transmission begins**. It synchronises sequence numbers and ensures that both the client and server are ready to exchange data reliably.
1. **SYN**: The client sends a **SYN** packet to the server to request a connection.
2. **SYN-ACK**: The server responds with SYN-ACK, acknowledging the client's request and sending its own connection request.
3. **ACK**: The client sends an ACK to acknowledge the server's request.

After these three steps, the TCP connection is established and data can be transmitted.

### TCP Four-Way Handshake
The TCP four-way handshake is the process used to **terminate an established TCP connection**. It allows both sides to independently close their sending direction.
1. **FIN**: The client sends a FIN packet to indicate that it has finished sending data.
2. **ACK**: The server sends an ACK to acknowledge the client's FIN.
3. **FIN**: When the server has also finished sending data, it sends a FIN to the client.
4. **ACK**: The client sends an ACK to acknowledge the server's FIN.

After these steps, the TCP connection is closed.

![TCP Four-Way Handshake](../Attachments/Images/TCP%20Four-Way%20Handshake.png)
### TCP Sequencing/Acknowledgment
TCP sequencing and acknowledgment mechanisms ensure that **data is delivered reliably and in the correct order** between the sender and receiver.
- Hosts set random initial sequence number. Each TCP byte is assigned a sequence number.
- The receiver uses sequence numbers to arrange data in the correct order.
- The receiver tells the sender which data has been successfully received.
- The ACK number indicates the **next byte the receiver expects**.
- **Forward acknowledgement** is used to indicate the sequence number of the next segment the host expects to receive.

![TCP Sequence & Acknowledgement](../Attachments/Images/TCP%20Sequence%20&%20Acknowledgement.png)
### TCP Retransmission
TCP retransmission is the process of sending TCP data again when the **sender determines that the original segment was probably lost or not successfully received**.
- Ensures reliable delivery of data.
- The receiver acknowledges successfully received data.
- TCP uses sequence numbers to identify which data needs to be retransmitted.
- If an expected ACK does not arrive within a certain period, TCP retransmits the segment.

![TCP Retransmission](../Attachments/Images/TCP%20Retransmission.png)
### TCP Flow Control - Window Size
The TCP header contains a window field that communicates the receiver's available buffer space.
- Acknowledging every single segment, no matter the size, is inefficient.
- TCP header's **window size** field allows more data to be sent before an acknowledgement is requried.
- A sliding window can be used to dynamically adjust how large the windows size is.

![TCP Flow Control - Window Size](../Attachments/Images/TCP%20Flow%20Control%20-%20Window%20Size.png)
## UDP (User Datagram Protocol)
UDP is a layer 4 transport protocol that provides **connectionless** and **low-overhead** communication between applications.
- UDP does not establish a connection before sending data.
- UDP **can detect corruption using a checksum**, but it doesn't provide reliability. If a segment is lost, UDP has no mechanism for retransmitting it. Segments are sent using a **best-effort** approach.
- UDP does not provide sequencing. If segments arrive out of order, UDP has no mechanism for putting them back in order.
- UDP does not provide flow control. It has no mechanism, such as TCP's window size, to control the flow of data.
- Example use cases are live video streaming, online gaming, VoIP calls or real-time applications where speed matters more than reliability.
## Comparing TCP & UDP
- TCP provides more features than UDP, but at the cost of additional overhead.
- For applications that require reliable communications, such as downloading a file, TCP is preferred.
- For applications like real-time voice and video, UDP is preferred.
- There are some applications that use UDP, but provide reliability withing the application itself.
- Some applications use both TCP and UDP, depending on the situation.
