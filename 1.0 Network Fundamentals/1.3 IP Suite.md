# 1.3 IP Suite
## Introduction
A **protocol** is a set of rules defining how data should be communicated between devices over a network.

A **standard** is an agreed-upon specification that describes how a protocol or technology should work.
- With **vendor-neutral** standards, devices of all types can communicate with each other.

**IEEE (Institute of Electrical and Electronics Engineers)** develops many of the technologies used on networks:
- Ethernet (802.3)
- Wi-Fi (802.11)

**IETF (Internet Engineering Task Force)** is an open community that defines protocols used on Internet:
- TCP, UDP, IP, HTTP, DNS, etc.
- Publishes standards in documents called **RFCs (Request for Comments)**.
## Layered Models
A layered model in computer networking divides communication into different layers, with each layer responsible for a specific task. Each layer works with the layers above and below it to ensure data is transmitted correctly.
### TCP/IP Model
The TCP/IP model is a layered networking framework that explains how data is communicated between devices over a network using standardized protocols to ensure reliable and efficient transmission.
- Defined as a **four-layer architecture** consisting of Application, Transport, Internet and Link layers.
- Simpler and more practical than the seven-layer OSI model.
- Serves as the core framework of the modern internet and networking systems.
#### Application Layer
This is the top layer of the TCP/IP model, where applications like web browsers, email clients, and file-sharing tools interact with the network.
- Acts as a bridge between user applications and lower network layers.
- Handles data formatting so information is correctly understood by both sender and receiver.
- Protocols at this layer define message formats and rules for specific tasks, such as:
	- Browsing web pages. (HTTP/HTTPS)
	- Transferring files. (FTP, TFTP)
	- Sending and receiving emails. (SMTP, POP3, IMAP)
#### Transport Layer
Ensures reliable and efficient delivery of data between devices, managing segmentation, ordering, and retransmission as needed.
- TCP checks for errors, resends lost data, and ensures correct order.
- UDP provides low-latency, connectionless delivery without error checking.
- Provides end-to-end communication between application processes using **port numbers**.
##### TCP (Transmission Control Protocol)
TCP is used when reliability and accuracy are important. It ensures that data is delivered exactly as sent.
- TCP establishes a connection between sender and receiver before sending data.
- TCP detects errors in the data using checksums to ensure integrity.
- If any data is lost or corrupted during transmission, TCP automatically resends it.
- TCP ensures packets arrive in the correct sequence.
- Example use cases are loading web pages, downloading files, sending emails or any application where data must be complete and accurate.
##### UDP (User Datagram Protocol)
UDP is used when speed is more important than perfect accuracy. It is faster but does not guarantee reliable delivery.
- UDP **can detect corruption using a checksum**, but it doesn't provide reliability mechanisms such as acknowledgments and retransmissions.
- Lost or damaged data is not resent.
- Packets may arrive out of order, and the protocol does not fix it.
- Because it avoids extra checks and connections, UDP is faster and uses fewer resources.
- Example use cases are live video streaming, online gaming, VoIP calls or real-time applications where speed matters more than reliability.
#### Internet Layer
Responsible for addressing, packaging, and routing data packets so they can travel across networks and reach the correct destination device. It ensures that data can move between different networks efficiently.
- Uses IP addresses to identify source and destination devices.
- Routers operate mainly at this layer, using the message's destination IP address to forward the message toward its final destination.
- Primarily uses **IP (Internet Protocol)**, along with supporting protocols like **ICMP (Internet Control Message Protocol)** for error reporting.
##### IP (Internet Protocol)
IP is responsible for **logical addressing and routing packets** from a source device to a destination device across different networks.
- Provides **logical addressing** using IPv4 or IPv6 addresses.
- Enables **packet delivery between different networks**.
- Routers use the destination IP address to make forwarding decisions.
- Does **not** guarantee delivery.
##### ICMP (Internet Control Message Protocol)
ICMP is used by network devices to **send error messages and operational information** about IP packet delivery.
- Works alongside IP.
- Used for **diagnostics and troubleshooting**.
- Does **not** provide reliable data delivery.
- Common messages include:
	- Echo Request / Echo Reply (used by `ping`)
	- Destination Unreachable
	- Time Exceeded
	- Redirect
#### Link Layer
Responsible for physically transmitting data over network hardware, including cables, switches, and wireless connections. It handles how data is formatted for the network medium and ensures it reaches the next device on the path.
- Sends and receives raw bits over physical media like Ethernet cables, fiber optics or Wi-Fi.
- Organizes data into frames for proper transmission and recognition by devices.
- Uses **MAC (Media Access Control) addresses** to identify devices within the same network segment.
-  Uses **ARP (Address Resolution Protocol)** for address resolution.

This layer is divided into two separate layers in the **five-layer model: the Data Link Layer and the Physical Layer**.
- Data Link Layer is responsible for frames, MAC addresses, and communication between devices on the same network segment.
- Physical Layer is responsible for transmitting raw bits as electrical, optical, or radio signals over the physical medium.
##### ARP (Address Resolution Protocol)
ARP is used in **IPv4 networks** to **discover the MAC address associated with a known IPv4 address** on the local network.
- Maps IPv4 address to MAC address.
- Used when a device knows the destination IP but needs the destination MAC address to create an Ethernet frame.
- Works only within the **local network/broadcast domain**.
- It consists of two messages, an ARP Request and an ARP Reply.
- ARP Request is sent as a **broadcast**. ARP Reply is sent as a **unicast**.
- If the destination is on another network, the host ARPs for the MAC address of its default gateway rather than the remote destination.
#### Encapsulation and Decapsulation
Encapsulation is the process of **adding headers (and sometimes trailers) to data as it moves down the TCP/IP layers** before transmission over the network.

Decapsulation is the reverse process. When the receiving device gets the frame, **each layer removes and examines the information added by the corresponding sending layer.**

|    Layer    |               Process                |    PDU (Protocol Data Unit)    |
| :---------: | :----------------------------------: | :----------------------------: |
| Application |             Creates Data             |              Data              |
|  Transport  |         Adds TCP/UDP Header          | Segment (TCP) / Datagram (UDP) |
|  Internet   |            Adds IP Header            |             Packet             |
|    Link     | Adds Ethernet/Wi-Fi Header + Trailer |             Frame              |
|  Physical   |       Converts to Bits/Signals       |              Bits              |
