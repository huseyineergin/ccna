# 1.5 IPv4 Addressing
## Introduction
### OSI Model - Network Layer (L3)
- Provides connectivity between end hosts on **different networks**, such as outside the LAN.
- Uses **IP addresses for logical addressing**.
- Determines the best path between the source and destination.
- Routers operate primarily at this layer and forward packets between networks.

## IPv4 Header
The IPv4 packet header consists of 14 fields, of which 13 are required.
### Version
It is the first header field in an IP packet. For IPv4, this is always equal to 4.
- **4 bits** long.
- Identifies the version of IP used.
- IPv4 = 4 (0100), IPv6 = 6 (0110)
### IHL (Internet Header Length)
The IPv4 header is variable in size due to the optional 14th field (Options). The IHL field **contains the size of the IPv4 header**.
- **4 bits** long.
- Identifies the length of the header in **4-byte increments**.
- The minimum value is 5, which indicates a length of $5 \times 4\text{ bytes} = 20\text{ bytes}$.
- The maximum value is 15, which indicates a length of $15 \times 4\text{ bytes} = 60\text{ bytes}$.
### DSCP (Differentiated Services Code Point)
The DSCP field is used to **classify network traffic and provide quality of service (QoS)** on networks. Network devices use DSCP markings to determine how different types of traffic should be handled, helping provide appropriate levels of **priority, delay, jitter and packet-loss treatment**.
- **6 bits** long.
- Identifies different types or classes of network traffic.
- Allows network devices to apply different forwarding and queuing policies.
- Used to **prioritize delay-sensitive data**, such as streaming voice and video.
### ECN (Explicit Congestion Notification)
The ECN field allows **end-to-end notification of network congestion without dropping packets**.
- **2 bits** long.
- Optional feature that requires both endpoints, as well as the underlying network infrastructure, to support it.
### Total Length
This field **defines the entire packet size in bytes, including header and data**.
- **16 bits** longs.
- The minimum size is 20 bytes (header without data) and the maximum is 65,535 bytes.
### Identification
If a packet is fragmented due to being too large, this field is used to identify which packet the fragment belongs to.
- **16 bits** long.
- Packets are fragmented **if larger than the maximum transmission unit (MTU)**.
- All fragments of the same packet will have their own IPv4 header with the same value in this field.
- Fragments are reassembled by the receiving host.
#### MTU (Maximum Transmission Unit)
MTU is the **size of the largest packet that can be sent in a single network layer transaction** over a particular network link, without needing to split it into smaller packets. MTU relates to, but is not identical to the maximum frame size that can be transported on the data link layer, e.g., Ethernet frame.
- Larger MTU is associated with reduced overhead. Smaller MTU values can reduce network delay.
- Suppose a network has an MTU of **1500 bytes** (common for Ethernet):
	- Packet ≤ 1500 bytes → can be transmitted normally.
	- Packet > 1500 bytes → it may need to be fragmented.
### Flags
This field is used to control/identify fragments. There are three flags defined within this field.
- **3 bits** long.
- **Bit 0, Reserved (R)**: Reserved, always set to 0.
- **Bit 1, Don't Fragment (DF)**: Specifies whether the packet can be fragmented or not.
- **Bit 2, More Fragments (MF)**: For unfragmented packets, the MF flag is set to 0. For fragmented packets, all fragments except the last have the MF flag set to 1.
### Fragment Offset
This field specifies the offset of a particular fragment relative to the beginning of the original unfragmented packet.
- **13 bits** long.
- Used to indicate the position of the fragment within the original, unfragmented packet.
- Allows fragmented packets to be reassembled even if the fragments arrive out of order.
- The fragmentation offset value for the first fragment is always 0.
### TTL (Time to Live)
The TTL field **limits a packet's lifetime** to prevent network failure in the event of a routing loop.
- **8 bits** long.
- Originally designed to indicate the packet's maximum lifetime in seconds. In practice, it is used as a hop count. Each time the packet arrives at a router, the router decrements the TTL by one.
- A router will drop a packet with a TTL of 0.
- Recommended default TTL is 64.
### Protocol
This is a **8 bits** long field that **identifies the protocol encapsulated in the data portion** of the packet (L4PDU). Some of the common payload protocols include:

| Protocol Number |            Protocol Name             | Abbreviation |
| :-------------: | :----------------------------------: | :----------: |
|        1        |  Internet Control Message Protocol   |     ICMP     |
|        2        |  Internet Group Management Protocol  |     IGMP     |
|        6        |    Transmission Control Protocol     |     TCP      |
|       17        |        User Datagram Protocol        |     UDP      |
|       41        |          IPv6 Encapsulation          |    ENCAP     |
|       89        |       Open Shortest Path First       |     OSPF     |
|       132       | Stream Control Transmission Protocol |     SCTP     |
### Header Checksum
The IPv4 header checksum field is used for **error checking of the header**. Before sending the packet, the sender calculates a checksum from the header and adds it to the header.
- **16 bits** long.
- Used to check for **errors only in the IPv4 header**, not in the encapsulated data.
- Protocols like TCP or UDP can use their **checksum to check errors in the encapsulated data**.
- When a router receives a packet, it calculates the checksum of the header and compares it to the one in this field. If they do not match, the router drop the packet.
### Source Address
This **32 bits** long field contains the IPv4 address of the sender of the packet. It may be changed in transit by network address translation (NAT).
### Destination Address
This **32 bits** long field contains the IPv4 address of the intended receiver of the packet. It may also be affected by NAT.
### Options
This is an optional field used to carry additional information or instructions for handling a packet.
- **0-320 bits** long.
- Rarely used.
- If IHL is greater than 5, it means that the options field is present and must be considered.
## IPv4 Subnetting
**CIDR (Classless Inter-Domain Routing)** is a method of IP address allocation that allows more efficient use of IP addresses. Unlike traditional class-based addressing, CIDR allocates IP addresses based on a network prefix rather than a fixed class.

### VLSM (Variable-Length Subnet Masking)
VLSM is a subnetting technique that **divides an IP network into subnets of different sizes**. Unlike fixed-length subnet masking (FLSM), which uses the same subnet mask for all subnets, **VLSM uses multiple subnet masks within the same network** according to the number of hosts required by each subnet.
